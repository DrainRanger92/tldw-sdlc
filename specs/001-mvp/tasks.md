## Текущий инкремент

### T-001: Каркас пакета app/tldw, точка входа и конфиг из env
- тип: app
- статус: done
- зависит: —
- размер: M

**Описание**
Создать пакет `app/tldw/` со слоями `handlers/`, `services/`, `adapters/`, `storage/`,
точку входа `app/main.py`, метаданные `app/pyproject.toml` (Python 3.11+, aiogram 3,
httpx, youtube-transcript-api, yt-dlp, pytest, ruff) и загрузчик конфига. Все секреты
и настройки — только из env/`app/.env`: `TELEGRAM_BOT_TOKEN`, ключ и модель LLM,
allowlist Telegram user ID, порог длительности видео. Без этого каркаса остальным
задачам MVP некуда лечь.

**Критерии приёмки**
- [ ] `app/pyproject.toml` фиксирует Python 3.11+, aiogram 3, httpx, youtube-transcript-api, yt-dlp, pytest, ruff и настройки ruff; окружение ставится командой из `app/AGENTS.md`
- [ ] Существуют `app/main.py` и пакет `app/tldw/` со слоями handlers/services/adapters/storage (в каждом `__init__.py`)
- [ ] Конфиг читается только из env; отсутствие `TELEGRAM_BOT_TOKEN` или ключа LLM даёт понятную ошибку при старте, а не падение в рантайме
- [ ] `app/.env.example` перечисляет все переменные приложения без реальных секретов; `app/data/` в `.gitignore`
- [ ] `app/main.py` собирает приложение при фиктивных env и завершается с понятным сообщением, если env неполные
- [ ] `pytest -q` и `ruff check .` проходят в `app/`; тесты не ходят в сеть и не требуют токенов

### T-002: Модель заметки и рендер .md по шаблону Obsidian
- тип: app
- статус: done
- зависит: T-001
- размер: M

**Описание**
Сделать в `services/` модель заметки и рендер в Obsidian-совместимый `.md` по полному
шаблону из `specs/product.md`: YAML frontmatter (`title`, `source`, `channel`,
`duration`, `date`, `tags`, `status: processed`) и секции `## TL;DR` (3–5 предложений),
`## Ключевые идеи` (5–10 пунктов), `## Таймкоды` (по смысловым блокам),
`## Цитаты` (2–3 с таймкодами), `## Что проверить`. Рендер безопасно экранирует YAML
и формирует имя файла.

**Критерии приёмки**
- [ ] Рендер даёт frontmatter ровно с полями title, source, channel, duration, date, tags, status: processed
- [ ] Все пять секций присутствуют в порядке шаблона из `specs/product.md`
- [ ] YAML корректен для title и tags с кавычками, двоеточиями и юникодом; дата в ISO-формате
- [ ] Имя файла — slug заголовка без недопустимых символов, с расширением `.md`; для пустого title — непустой фолбэк
- [ ] Юнит-тесты покрывают полный шаблон, спецсимволы в YAML и пустые значения

### T-003: Адаптер YouTube: ссылка, метаданные и транскрипт
- тип: app
- статус: done
- зависит: T-001
- размер: M

**Описание**
Реализовать `adapters/` для YouTube: валидация ссылки и извлечение video id
(`youtube.com/watch`, `youtu.be`, `youtube.com/shorts`), метаданные (title, channel,
duration) и транскрипт через `youtube-transcript-api` с fallback `yt-dlp`. Отсутствие
субтитров и не-YouTube ссылка — отдельные типизированные исключения, чтобы обработчик
мог показать понятную ошибку.

**Критерии приёмки**
- [ ] Поддерживаются `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`; id извлекается, не-YouTube ссылка отвергается типизированной ошибкой
- [ ] Транскрипт берётся через youtube-transcript-api, при его сбое — fallback yt-dlp; оба пути живут в адаптере
- [ ] Метаданные содержат title, channel и duration в секундах, когда доступны
- [ ] Нет субтитров → отдельное исключение, отличимое от «не YouTube» и сетевой ошибки
- [ ] Тесты на фейковом клиенте: успех, нет субтитров, неверная ссылка, срабатывание fallback — без сети и токенов

### T-004: Адаптер LLM: промпт конспекта и разбор ответа
- тип: app
- статус: done
- зависит: T-001
- размер: M

**Описание**
Реализовать `adapters/` для LLM: httpx-клиент с ключом и моделью из конфига, таймаутом
и повтором на 429/5xx. Промпт и шаблон заметки — ресурсы пакета, а не env; промпт
требует вернуть JSON строго по разделам шаблона. Ответ валидируется до модели заметки,
ошибки провайдера поднимаются как `LLMError`.

**Критерии приёмки**
- [ ] Промпт требует ровно разделы шаблона (TL;DR 3–5 предложений, 5–10 идей, таймкоды, 2–3 цитаты с таймкодами, что проверить) и ответ в JSON
- [ ] Ключ и модель LLM берутся из конфига (env); в коде, тестах и фикстурах секретов нет
- [ ] Битый JSON, отсутствие обязательных полей или пустой ответ → `LLMError`, а не частичная заметка
- [ ] Таймаут и HTTP-ошибки провайдера → `LLMError` с причиной в логе
- [ ] Тесты на `httpx.MockTransport`: успех, битый JSON, 500, таймаут — без сети

### T-005: Сервис конспекта: порог длительности, транскрипт → заметка
- тип: app
- статус: done
- зависит: T-002, T-003, T-004
- размер: M

**Описание**
Сервис в `services/` связывает адаптеры: проверяет длительность видео по порогу из
конфига (дефолт ~2 часа) и отказывает с `VideoTooLongError` без частичной заметки,
склеивает транскрипт с таймкодами, вызывает LLM и рендерит готовый `.md` по шаблону.

**Критерии приёмки**
- [ ] Видео длиннее порога из конфига → `VideoTooLongError`, `.md` не создаётся (частичной заметки нет)
- [ ] Порог задаётся конфигом, дефолт ~2 часа; поведение на границе `duration == порог` зафиксировано тестом
- [ ] Успешный путь возвращает модель заметки и готовый `.md` по шаблону T-002, поле `source` — исходная ссылка
- [ ] Таймкоды транскрипта сохраняются в промпте; если транскрипт усекается, усечение задокументировано и не ломает JSON
- [ ] Тесты с фейковыми адаптерами: успех, слишком длинное видео, нет субтитров, `LLMError`

### T-006: Telegram-обработчик: приём ссылки, «принял → обрабатываю → готово», отправка .md
- тип: app
- статус: done
- зависит: T-001, T-005
- размер: M

**Описание**
Обработчик в `handlers/` принимает сообщение со ссылкой, сразу отвечает «принял»,
обрабатывает видео в фоне без блокировки event loop, присылает «обрабатываю…» и затем
`.md`-документ с именем из шаблона и короткое «готово». Готовый файл сохраняется
в `app/data/` через слой `storage/`.

**Критерии приёмки**
- [ ] На ссылку бот отвечает «принял», затем «обрабатываю», затем присылает `.md`-документ и «готово»
- [ ] Тяжёлые вызовы (YouTube, LLM) не блокируют event loop: выполняются через `asyncio.to_thread` или executor
- [ ] Текст без ссылки → подсказка, что нужна ссылка на YouTube; если в тексте ссылка есть, обрабатывается первая (поведение покрыто тестом)
- [ ] Готовый `.md` сохраняется в `app/data/` (путь из конфига) до отправки и не попадает в git
- [ ] Тесты на фейковом боте (aiogram mock): успешный сценарий и текст без ссылки, без сети и токенов

## Бэклог

### T-007: Allowlist по Telegram user ID
- тип: app
- статус: pending
- зависит: T-006
- размер: S

**Описание**
Ограничить доступ к боту по allowlist из конфига: список Telegram user ID, пустой
список — доступ всем с предупреждением в лог при старте. Проверка выполняется до
разбора ссылки и до любых вызовов адаптеров, чтобы чужой запрос не тратил квоту LLM.

**Критерии приёмки**
- [ ] Allowlist читается из env как список ID (через запятую/пробелы), некорректное значение даёт понятную ошибку старта
- [ ] ID из списка проходит обработку, чужой ID получает сообщение «доступ закрыт» и не запускает обработку видео
- [ ] Проверка доступа выполняется до парсинга ссылки и до вызовов YouTube/LLM
- [ ] Пустой allowlist пропускает всех и пишет предупреждение в лог; поведение покрыто тестом
- [ ] Тесты: разрешённый ID, чужой ID, пустой список — без сети и токенов

### T-008: Понятные ошибки пользователю и логирование сбоев
- тип: app
- статус: pending
- зависит: T-005, T-006
- размер: S

**Описание**
Свести типизированные исключения сервисов и адаптеров к понятным сообщениям
пользователю: не YouTube, нет субтитров, слишком длинное видео, AI не ответил.
Неизвестные сбои — общее сообщение пользователю и полный стектрейс в лог без секретов
и полного транскрипта.

**Критерии приёмки**
- [ ] Каждый тип ошибки (не YouTube, нет субтитров, слишком длинное видео, AI не ответил) даёт своё понятное сообщение на русском без стектрейсов
- [ ] Неизвестная ошибка → общее сообщение пользователю и запись ERROR со стектрейсом в лог
- [ ] Сообщения и логи не содержат токенов, ключей API и полного транскрипта
- [ ] Тесты на каждый тип ошибки: пользователь видит ожидаемый текст, в логе есть причина
