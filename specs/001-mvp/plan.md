# План 001-mvp

Архитектура, стек и этапы MVP по `spec.md` этой спеки. Стек зафиксирован в
`app/AGENTS.md`; порядок задач и их статусы — в `tasks.md`.

## Стек

- Python 3.11+, пакетный менеджмент — `app/pyproject.toml`, окружение `app/.venv`.
- Telegram — aiogram 3; HTTP — httpx; субтитры — youtube-transcript-api с fallback
  yt-dlp.
- Тесты — pytest (офлайновые, без сети и токенов), линт — ruff.
- Конфигурация и секреты — только env/`app/.env`; ресурсы промпта и шаблона заметки
  живут в пакете, а не в env.

## Структура app/

```text
app/
  main.py                 точка входа
  tldw/
    bootstrap.py          сборка Bot/Dispatcher без сетевых вызовов
    config.py             Settings из env, fail-fast
    cli.py                --check-config, запуск polling
    logging_setup.py      логи без секретов
    handlers/             Telegram: приём ссылки, allowlist, ответы, ошибки
    services/             сценарии: заметка, транскрипт → конспект
    adapters/             YouTube и LLM, единственная граница внешних вызовов
    storage/              пути и запись файлов в каталог данных
  data/                   заметки и кэш, в .gitignore
  tests/                  офлайновые тесты и фейковые адаптеры
```

Правило слоёв: `handlers → services → adapters/storage`. Прямые импорты `httpx`,
`youtube_transcript_api` и `yt_dlp` вне `adapters/` запрещены; сборка приложения не
делает сетевых вызовов.

## Этапы

1. **Каркас** (T-001, сделано): пакет, точка входа, env-конфиг, сборка без сети,
   офлайновые тесты.
2. **Модель заметки и рендер** (T-002, сделано): frontmatter и полный
   Obsidian-шаблон, безопасное имя файла.
3. **Адаптеры** (T-003, T-004, сделано): YouTube (ссылка, метаданные,
   транскрипт с fallback) и LLM (промпт, JSON-ответ, `LLMError`).
4. **Сервис конспекта** (T-005, сделано): порог длительности, склейка
   транскрипта, вызов LLM, рендер `.md`.
5. **Telegram-сценарий** (T-006, сделано): «принял → обрабатываю → готово»,
   фоновая обработка, сохранение в `app/data/`.
6. **Доступ и ошибки** (T-007, T-008, сделано): allowlist до вызовов
   адаптеров, понятные сообщения и логирование.
7. **Сквозная проверка** (T-009, сделано): E2E-тест на фейковых адаптерах
   и README запуска.

MVP закрыт: T-001–T-009 выполнены, сквозной сценарий и README закреплены
E2E-тестом. Дальнейшие работы ведутся отдельными спеками, начиная с
`specs/002-user-note-templates/`.

## Риски и проверки

- Стоимость и задержка LLM — ограничить промпт и таймаут, повтор только на 429/5xx.
- Нестабильность субтитров YouTube — fallback yt-dlp и отдельная ошибка «нет
  субтитров».
- Длинные видео — отказ по порогу из конфига без частичной заметки.
- Регрессии — `pytest -q` и `ruff check .` в `app/` на каждом инкременте, тесты не
  ходят в сеть и не требуют токенов.
- Секреты — только env; проверка, что токены и полный транскрипт не попадают в логи.
