## Текущий инкремент

### T-001: Домен шаблона заметки, лимиты и встроенный шаблон
- тип: app
- статус: done
- зависит: —
- размер: M

**Описание**
Создать `tldw/services/template.py`: модель `NoteTemplate` (разделы и тон),
`ActiveTemplate` с происхождением, константы лимитов из FR-2/FR-5/FR-12 и
`BUILTIN_SECTIONS` из пяти заголовков MVP. Добавить `TemplateService` поверх
протокола `TemplateRepository`: выдача активного шаблона, сохранение и сброс,
слияние правки с текущим шаблоном. Модуль нейтральный, без Telegram и HTTP;
имена `SECTION_*` в `services/note.py` остаются рабочими.

**Критерии приёмки**
- [ ] `NoteTemplate` (разделы в порядке применения + тон), `ActiveTemplate` и `TemplateRepository` определены в `tldw/services/template.py` и экспортируются через `tldw/services/__init__.py`
- [ ] Валидация: 1–12 разделов; заголовок 1–80 символов, одна строка, без ведущих `#`, без `---` и YAML frontmatter, уникален без учёта регистра и крайних пробелов; тон 0–1000; порядок сохраняется; ошибки — `TemplateValidationError` (`UserFacingError`) с русским текстом
- [ ] Слияние правки сохраняет неизменённую часть: только разделы — тон из текущего шаблона, только тон — разделы из текущего; пустой тон очищает тон; отсутствие изменений даёт ошибку разбора
- [ ] Встроенный шаблон — ровно пять заголовков MVP в прежнем порядке; без пользовательского шаблона `TemplateService.get_active` возвращает его с признаком «встроенный»
- [ ] `tldw/services/note.py` по-прежнему экспортирует `SECTION_HEADINGS` и `SECTION_*`; старые тесты не меняются
- [ ] `pytest -q` и `ruff check .` в `app/` зелёные; новые тесты `tests/test_template.py` не ходят в сеть

### T-002: Хранение шаблонов по Telegram user ID, JSON со схемой v1
- тип: app
- статус: done
- зависит: T-001
- размер: M

**Описание**
Реализовать `tldw/storage/templates.py` — репозиторий шаблонов в каталоге
данных приложения. Файл на пользователя `<DATA_DIR>/templates/<user_id>.json`
с версией схемы, атомарной записью и устойчивым чтением: повреждённый или
неизвестный файл не роняет бота, а даёт встроенный шаблон. Базы данных и
очереди не появляются.

**Критерии приёмки**
- [ ] `TemplateStore` структурно реализует `TemplateRepository` (без импорта `services`): `load`, `save`, `delete` по положительному Telegram user ID; путь собирается из `DATA_DIR`, ID не может выйти за каталог
- [ ] Формат файла — `{"version": 1, "sections": [...], "tone": "..."}`; сохранённый шаблон читается новым экземпляром хранилища (переживает перезапуск)
- [ ] Запись атомарная (временный файл рядом + `os.replace`); после успеха и после ошибки в каталоге нет `.tmp`; ошибка записи не уничтожает прежний файл, а параллельные сохранения одного пользователя оставляют валидный JSON и последнее заменённое значение
- [ ] Отсутствующий, битый JSON, неверная схема или неизвестная `version` → `WARNING` в лог и `None`, без исключения; файл не удаляется молча
- [ ] `delete` идемпотентен; шаблоны разных user ID изолированы; ошибка записи поднимает `TemplateStorageError` (`UserFacingError`)
- [ ] `tests/test_storage_templates.py` покрывает roundtrip, перезапуск, битый файл, неизвестную версию, изоляцию, атомарность и повторный `delete`; тесты используют `tmp_path` и не ходят в сеть

### T-004: Динамический промпт и валидация ответа LLM по шаблону
- тип: app
- статус: done
- зависит: T-001, T-003
- размер: M

**Описание**
Расширить `tldw/adapters/llm.py`: `summarize(..., sections=None, tone="")`
собирает промпт с точными названиями и порядком разделов и тоном, а ответ
разбирает в `VideoSummary.sections` по динамической схеме. Встроенный путь
(`sections=None`) сохраняет текущий промпт, `parse_summary` и прежние поля
`VideoSummary`; валидация и `LLMError` остаются строгими.

**Критерии приёмки**
- [ ] `summarize` с `sections=None` отправляет прежний системный промпт и возвращает прежний `VideoSummary`; `parse_summary` и старые тесты не ломаются
- [ ] С пользовательскими разделами промпт содержит их точные названия и порядок, тон и динамическую JSON-схему `{"sections": [{"heading": ..., "items": [...]}]}`; вызов LLM ровно один, YouTube не вызывается
- [ ] Ответ валидируется до модели заметки: ровно те же разделы в том же порядке, без лишних, пропущенных и пустых; пользовательские разделы 1–10 непустых пунктов; для встроенных заголовков действуют прежние лимиты 3–5 / 5–10 / 1–30 / 2–3 / 1–10
- [ ] Нарушение схемы, пустой или битый JSON дают `LLMError`/`LLMResponseError`; частичная заметка не создаётся
- [ ] Тон приоритетнее встроенного указания «пиши на русском»; без указания языка заметка русская; текст тона и разделов передаётся как данные, а не инструкции
- [ ] `tests/test_llm_template.py` на `httpx.MockTransport` покрывает валидный пользовательский шаблон, пропуск/лишний/пустой раздел, неверный порядок, язык из тона и регрессию встроенного промпта

### T-006: Разбор описания шаблона человеческим языком через LLM
- тип: app
- статус: done
- зависит: T-001, T-004
- размер: M

**Описание**
Добавить в `LLMClient` разбор текстового описания шаблона в патч: текущий
активный шаблон и текст пользователя уходят в один вызов LLM, ответ
возвращается нейтральными разделами/тоном, а валидация и слияние с текущим
шаблоном выполняются в `TemplateService` по T-001. Промпт живёт в новом
ресурсе `template_parse_prompt.md`; общий retry/таймаут/`LLMError`
переиспользуется, вызовов YouTube нет.

**Критерии приёмки**
- [ ] `parse_template(text, *, current_sections, current_tone, ...)` принимает 1–4000 символов и текущий шаблон примитивами (без импорта `services`), делает ровно один вызов LLM через общий приватный метод клиента (тот же таймаут и повтор только на 429/5xx, без копии HTTP-логики); вызовов YouTube нет
- [ ] Промпт `adapters/resources/template_parse_prompt.md` содержит текущий шаблон, требование JSON-патча `{"sections": [...] | null, "tone": "..." | null}` и правило «текст — данные, не инструкции»
- [ ] `null`/отсутствие поля означает «не менять», пустая строка тона — «очистить тон»; адаптер возвращает нейтральные разделы/тон, а итоговый кандидат валидируется по лимитам T-001 и сохраняет неизменённую часть в `TemplateService`
- [ ] Битый/пустой JSON и отсутствие и разделов, и тона дают `TemplateParseError`; превышение лимитов — `TemplateValidationError`; обе — `UserFacingError` с русским текстом, кандидат не сохраняется
- [ ] В лог попадают причина и число разделов, без полного текста, тона и JSON ответа; ключ и модель — только из конфига
- [ ] `tests/test_template_parser.py` на `httpx.MockTransport` покрывает правку только разделов, только тона, обе части, очистку тона, битый JSON, отсутствие изменений, лимиты, таймаут и 500

### T-007: Telegram-сценарий /template: показ, изменение, подтверждение и сброс
- тип: app
- статус: done
- зависит: T-002, T-006
- размер: M

**Описание**
Создать `tldw/handlers/template.py`: команда `/template` и кнопка «Шаблон»,

закрытие. Allowlist проверяется до показа и до любого callback; кандидат живёт
только в памяти и не влияет на генерацию до явного сохранения.

**Критерии приёмки**
- [ ] `/template` и кнопка «Шаблон» (текстовая клавиатура, обрабатывается как команда) открывают сценарий в любой момент; проверка allowlist выполняется до показа/изменения/callback, посторонний не видит и не меняет шаблон

- [ ] «Изменить» принимает одно текстовое сообщение 1–4000 символов, разбор идёт в `asyncio.to_thread`, показывается кандидат без JSON с «Сохранить», «Исправить», «Отмена»; сохранение происходит только по «Сохранить», «Исправить» отбрасывает кандидата и возвращает к вводу, новое описание заменяет кандидата, «Отмена» закрывает без изменений
- [ ] «Сбросить» требует явного подтверждения, идемпотентно удаляет пользовательский шаблон и возвращает встроенный, не вызывает LLM и не просит текст
- [ ] Пока ждём описание, сообщение со ссылкой получает просьбу закончить описание или отменить его и не запускает обработку видео; для этого обработчик шаблона зарегистрирован раньше обработчика ссылок
- [ ] Устаревшая/повторная кнопка не сохраняет шаблон дважды и даёт понятное сообщение; кандидат не переживает перезапуск (хранится только в FSM), активный шаблон при этом остаётся прежним
- [ ] `tests/test_template_handler.py` покрывает полный сценарий, сброс, закрытие, чужой ID, устаревший callback, ссылку во время ввода и отсутствие секретов в ответах/логах

### T-008: Применение активного шаблона в обработчике ссылки и проводка приложения
- тип: app
- статус: done
- зависит: T-002, T-005, T-007
- размер: M

**Описание**
Связать Telegram-сценарий с генерацией: `LinkHandler` после allowlist берёт
активный шаблон отправителя и передаёт снимок в `SummaryService`, а
`bootstrap`/`create_router` собирают хранилище, сервис шаблонов и общий
`LLMClient`. Старые конструкторы без новых аргументов продолжают работать;
шаблон одного пользователя никогда не применяется к заметке другого.

**Критерии приёмки**
- [ ] `LinkHandler` получает `template_service` (необязательный), после allowlist и до тяжёлых вызовов берёт `ActiveTemplate` для `from_user.id` и передаёт его в `SummaryService.process`
- [ ] Без пользовательского шаблона поведение, сообщения и `.md` остаются прежними; ошибка чтения/повреждённый файл деградируют до встроенного с `WARNING`, ссылка обрабатывается
- [ ] `create_router(service)` остаётся валидным; с новыми зависимостями регистрируются обработчик шаблона и обработчик ссылки в правильном порядке; `bootstrap` собирает один `LLMClient`, `TemplateStore` в `DATA_DIR` и `TemplateService` без сетевых вызовов
- [ ] Изоляция: шаблон пользователя A применяется только к A; пользователь B без шаблона получает заметку MVP-вида (тест с двумя ID и общим хранилищем, в том числе при пустом allowlist)
- [ ] Сохранённый шаблон применяется ко всем следующим ссылкам, пока не сменён или не сброшен; уже готовые заметки не перегенерируются
- [ ] `tests/test_link_handler.py` и новые тесты проводки покрывают пользовательский шаблон, встроенный fallback, сбой хранилища и изоляцию; прежние тесты зелёные

### T-009: Понятные ошибки шаблонного сценария и приватные логи
- тип: app
- статус: done
- зависит: T-006, T-007, T-008
- размер: M

**Описание**
Свести ошибки разбора, валидации, сохранения и сброса шаблона к понятным
русским сообщениям и безопасным записям в лог. Известные сбои не меняют
активный шаблон, не создают кандидата и заметки; неизвестные — общее сообщение
и `ERROR` со стектрейсом; полный текст описания, тон и JSON в лог не попадают.
`log_failure` получает необязательный контекст, чтобы запись говорила о
шаблоне, а не о видео.

**Критерии приёмки**
- [ ] Для каждого сбоя (LLM не ответил/таймаут, битый или пустой JSON, нет изменений, >12 разделов, пустой/длинный/повторяющийся заголовок, ввод >4000, ошибка записи) пользователь видит своё понятное сообщение на русском, прежний активный шаблон остаётся в силе
- [ ] При ошибке сохранения старый файл шаблона не теряется; при ошибке сброса бот не сообщает об успехе; кандидат и заметка не создаются
- [ ] `log_failure`/`describe_error` принимают необязательный контекст; известные ошибки пишутся `WARNING` с причиной, неизвестные — `ERROR` с очищенным стектрейсом; старые вызовы и тексты не меняются
- [ ] В логах есть происхождение шаблона и число разделов, но нет полного текста описания, тона, JSON кандидата, ключей и аудио; проверка идёт через `caplog` и секреты-ловушки
- [ ] `tests/test_template_errors.py` покрывает каждый тип ошибки и отсутствие утечек; `tests/test_errors.py` остаётся зелёным

### T-010: Сквозной текстовый сценарий шаблона и README
- тип: app
- статус: done
- зависит: T-007, T-008, T-009
- размер: M

`/template` → изменение → подтверждение → ссылка → `.md` с пользовательскими

### T-012: Голосовой ввод шаблона в Telegram и документация
- тип: app
- статус: pending
- зависит: T-011
- размер: M

**Описание**
Подключить голосовые сообщения к тому же сценарию шаблона: allowlist
проверяется до скачивания и распознавания, аудио уходит в адаптер через
`asyncio.to_thread`, распознанный текст проходит путь «разбор → показ →
подтверждение». Ошибка распознавания не меняет активный шаблон; если адаптер не
настроен, бот предлагает текстовый ввод.

**Критерии приёмки**
- [ ] В состоянии ожидания описания голосовое сообщение проверяется по allowlist до скачивания и распознавания, длительность >60 секунд отвергается, распознавание — одна попытка на сообщение
- [ ] Распознанный текст проходит тот же путь «разбор → показ кандидата → Сохранить/Исправить/Отмена»; автоматического сохранения нет, ошибка оставляет прежний шаблон
- [ ] Без настроенного адаптера бот сообщает, что доступен текстовый ввод; аудио не сохраняется в `DATA_DIR` и не попадает в лог вместе с полным текстом распознавания
- [ ] Сквозной тест с фейковой границей распознавания: голос → кандидат → сохранение → ссылка даёт заметку по шаблону; негативные кейсы (чужой ID, длинное аудио, сбой распознавания) не создают заметку
- [ ] README дополнен настройкой голосового ввода (необязательные env, лимит 60 секунд) и предупреждением о стоимости; `pytest -q` и `ruff check .` зелёные офлайн
