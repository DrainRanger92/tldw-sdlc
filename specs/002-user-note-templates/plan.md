# План 002-user-note-templates

Архитектура, стек и этапы работ по `spec.md` этой спеки. Базовая линия —
закрытый MVP `specs/001-mvp/` (Python-пакет `app/tldw/`, 371 офлайновый тест,
версия 0.13.0). Порядок задач, зависимости и критерии — в `tasks.md`.

## Стек

- Python 3.11+, пакет `app/tldw/`, окружение `app/.venv`, метаданные —
  `app/pyproject.toml`.
- Telegram — aiogram 3 (InlineKeyboard, FSM `MemoryStorage`), HTTP — httpx.
- Тесты — pytest (офлайн, без сети и токенов), линт — ruff.
- Текстовому сценарию **новые обязательные зависимости и env-переменные не
  нужны**. Голосовой ввод (бэклог) добавляет только необязательные настройки
  адаптера распознавания речи; ключ — из env/`app/.env`.
- Шаблоны — пользовательские данные в каталоге данных (`DATA_DIR`, по умолчанию
  `app/data/`), без базы данных и очереди. Версию и CHANGELOG ведёт
  оркестратор, а не задачи приложения.

## Архитектура

Слои не меняются: `handlers → services → adapters/storage`, плюс нейтральные
`config.py`, `access.py`, `errors.py`. Обработчики не импортируют `httpx` и не
содержат бизнес-логики; внешние вызовы — только через адаптеры. Тяжёлые
синхронные вызовы уходят в `asyncio.to_thread`.

### Домен шаблона — `tldw/services/template.py`

Новый нейтральный модуль, не знающий про Telegram и HTTP:

- `NoteTemplate` — frozen dataclass: `sections: tuple[str, ...]` (названия без
  `##`, в порядке применения) и `tone: str`;
- `ActiveTemplate` — шаблон плюс происхождение (`builtin` / `user`) для
  человеческого показа и лога;
- константы лимитов в коде, а не в env: 1–12 разделов, заголовок 1–80 символов,
  тон 0–1000, ввод описания 1–4000; пунктов в пользовательском разделе 1–10;
- нормализация и валидация: одна строка, без ведущих `#`, без `---` и YAML
  frontmatter, уникальность без учёта регистра и крайних пробелов; порядок
  разделов сохраняется;
- `BUILTIN_SECTIONS` — пять заголовков MVP в текущем порядке;
  `tldw/services/note.py` импортирует их и сохраняет прежние имена
  `SECTION_*`/`SECTION_HEADINGS` как алиасы, чтобы не ломать публичный API;
- `TemplateService` — сценарии поверх протокола `TemplateRepository`:
  `get_active(user_id)` (пользовательский или встроенный), `save(user_id,
  template)`, `reset(user_id)`; слияние правки `TemplatePatch` с текущим
  активным шаблоном: отсутствующее поле сохраняется, пустой тон очищает тон,
  отсутствие изменений — ошибка разбора;
- `TemplateValidationError` — `UserFacingError` с понятным русским текстом.

### Хранение — `tldw/storage/templates.py`

- Файл на Telegram user ID: `<DATA_DIR>/templates/<user_id>.json`; ID —
  положительное целое, имя файла собирается без пользовательских путей.
- JSON с версией схемы: `{"version": 1, "sections": [...], "tone": "..."}`.
- Запись атомарная, как у заметок: временный файл в том же каталоге +
  `os.replace`; ошибка записи не трогает прежний файл, временных файлов не
  остаётся. Одновременные сохранения одного пользователя дают валидный файл,
  действует последнее заменённое.
- Отсутствующий, повреждённый или неизвестный по `version` файл — `WARNING` в
  лог и `None` (то есть встроенный шаблон), без падения. Удаление идемпотентно.
- `TemplateStorageError` — `UserFacingError` для ошибок записи.
- `TemplateStore` структурно реализует `TemplateRepository` (duck typing, без
  импорта `services`), поэтому слой хранения не зависит от домена.
- Каталог `templates/` живёт внутри `DATA_DIR`, который уже исключён из git.

### Динамическая заметка — `tldw/services/note.py`

- Новые `SectionKind` (`paragraph`, `bullets`, `timeline`, `quotes`,
  `checklist`, `custom`) и `NoteSection(heading, kind, items)`.
- `Note` получает необязательное поле `sections: tuple[NoteSection, ...] = ()`.
  Если оно заполнено, `render_note` рендерит разделы в заданном порядке; если
  нет — работает прежний путь по пяти полям, поэтому старые тесты и встроенный
  шаблон не меняются.
- Для заголовков, совпадающих с встроенными без учёта регистра и крайних
  пробелов, сохраняется привычный формат: абзац, пункты, таймкоды, цитаты,
  чеклист. Остальные разделы — `## Название` и маркированный список.
- Frontmatter из 7 полей, экранирование YAML и имя файла не меняются;
  пользовательский заголовок не может разорвать frontmatter или добавить
  служебный раздел.
- `build_note` умеет собирать заметку из динамических разделов, сохраняя
  прежние поля метаданных и `source`.

### Генерация по шаблону — `tldw/adapters/llm.py`

- Адаптер остаётся единственной границей LLM и не импортирует `services`.
  Поэтому шаблон передаётся примитивами: `summarize(transcript, *, title,
  channel, sections=None, tone="")`; `sections=None` — прежний встроенный путь.
- Встроенный путь сохраняет текущий промпт и `parse_summary` без изменений.
  Динамический путь подставляет в `summary_prompt.md` точные названия и порядок
  разделов и тон, а также схему ответа (`{{RESPONSE_SCHEMA}}`):
  `{"sections": [{"heading": "...", "items": [...]}]}`.
- Валидация ответа до сборки заметки: ровно те же разделы в том же порядке, без
  лишних, пропущенных и пустых; для пользовательских разделов 1–10 непустых
  пунктов; для встроенных заголовков действуют прежние ограничения (3–5, 5–10,
  1–30, 2–3, 1–10). Нарушение — `LLMError`/`LLMResponseError`, частичной
  заметки нет.
- Тон пользователя приоритетнее встроенного «пиши на русском»; без указания
  языка заметка остаётся русской. Текст тона и разделов передаётся как данные,
  инструкции из него не выполняются.
- `VideoSummary` получает `sections` для динамического пути. Прежние поля и
  сравнение со старыми тестами сохраняются: встроенный разбор заполняет
  привычные поля, сравнение не ломается.

### Разбор описания шаблона — `tldw/adapters/llm.py`

- Новый ресурс `adapters/resources/template_parse_prompt.md`; системный промпт
  получает текущий активный шаблон и требование вернуть JSON-патч:
  `{"sections": [...] | null, "tone": "..." | null}`. `null`/отсутствие поля —
  «не менять», пустая строка тона — «очистить тон».
- Один вызов LLM на одно изменение через тот же клиент, таймаут и повтор только
  на 429/5xx; вызовов YouTube нет. Общий приватный метод запроса выносится из
  `summarize`, чтобы не дублировать retry/таймаут/`LLMError`.
- Адаптер возвращает нейтральный результат (`sections: tuple[str, ...] | None`,
  `tone: str | None`), а доменный `TemplatePatch` и слияние живут в
  `services/template.py`: адаптер не импортирует `services` и не знает модель
  шаблона.
- Ввод 1–4000 символов; ответ строго валидируется: битый/пустой JSON и
  отсутствие и разделов, и тона — `TemplateParseError`; нарушение лимитов —
  `TemplateValidationError` из T-001; обе — `UserFacingError` с русским
  текстом, кандидат не сохраняется.
- В лог попадают только причина и число разделов, без полного текста, тона и
  JSON кандидата.

### Telegram-сценарий — `tldw/handlers/template.py`

- Команда `/template` и текстовая кнопка «Шаблон» доступны в любой момент.
  Allowlist (`AccessPolicy`) проверяется первой строкой и для сообщений, и для
  callback; просмотр не вызывает LLM и YouTube.
- Показ активного шаблона человеческим текстом: «встроенный» либо
  пронумерованные разделы и тон (или «тон не задан»). Действия — inline-
  клавиатура «Изменить», «Сбросить», «Закрыть».
- FSM `MemoryStorage`: состояние ожидания описания и состояние подтверждения.
  Кандидат хранится только в памяти FSM, поэтому не переживает перезапуск;
  активный шаблон при этом остаётся прежним.
- «Изменить» → одно текстовое сообщение 1–4000 символов → разбор в
  `asyncio.to_thread` → показ кандидата (номер, разделы, тон) → «Сохранить» /
  «Исправить» / «Отмена». Сохраняет только «Сохранить»; «Исправить»
  отбрасывает кандидата и возвращает к вводу; «Отмена» закрывает сценарий.
- Пока ждём описание, сообщение со ссылкой не запускает обработку видео: бот
  просит закончить описание или отменить его. Для этого обработчик шаблона
  регистрируется в роутере раньше обработчика ссылок и при активном состоянии
  забирает сообщение себе.
- «Сбросить» требует явного подтверждения, удаляет пользовательский шаблон,
  идемпотентен, не вызывает LLM и не просит текст. Устаревшая или повторная
  кнопка не сохраняет дважды и даёт понятное сообщение.
- Колбэки не содержат текста шаблона; кандидат берётся из FSM по user ID.

### Проводка и обработчик ссылки

- `handlers/router.py`: `create_router(service, *, allowed_user_ids=(),
  template_service=None, template_parser=None)`. Старый вызов
  `create_router(service)` остаётся валидным: без зависимостей шаблонов
  регистрируется только обработчик ссылок.
- `bootstrap.py`: один `LLMClient` на приложение, `TemplateStore` в
  `DATA_DIR`, `TemplateService`; зависимости передаются в роутер. Сборка
  по-прежнему не ходит в сеть.
- `handlers/link.py`: после allowlist и до тяжёлых вызовов берёт снимок
  активного шаблона для отправителя и передаёт его в `SummaryService.process`.
  Ошибка чтения шаблона деградирует до встроенного с `WARNING`, ссылка не
  теряется.
- `SummaryService.process(url, *, template: ActiveTemplate | None = None)`:
  `None` — прежнее поведение; иначе один вызов LLM с разделами/тоном,
  динамическая сборка заметки и рендер; происхождение шаблона берётся из
  `ActiveTemplate` для лога. Снимок берётся один раз на обработку, смена
  шаблона во время генерации не влияет.

### Ошибки и наблюдаемость

- Разбор/валидация/хранение шаблона поднимают типизированные
  `UserFacingError`; `errors.log_failure` получает необязательный контекст
  («шаблон» / «заметка»), чтобы запись в лог была точной, но старые вызовы и
  тексты не менялись.
- Пользователь видит понятное русское сообщение, прежний активный шаблон
  остаётся в силе, кандидат не сохраняется, заметка не создаётся.
- В лог: факт применения (встроенный/пользовательский), число разделов, причина
  сбоя. Не пишутся: полный текст описания и тона, JSON кандидата, ключи,
  аудио и полный транскрипт. Очистка — существующим `sanitize_log_text`.

      template.py        домен, лимиты, TemplateService, слияние правки

    adapters/

    bootstrap.py         сборка TemplateStore/TemplateService/LLMClient
  data/templates/        пользовательские шаблоны, в .gitignore

## Этапы

1. **Домен и хранение** (T-001, T-002): модель шаблона, лимиты, встроенный
   шаблон, слияние правки, атомарный JSON на пользователя. Приложение работает
   как MVP: шаблоны ещё не применяются к заметкам.
2. **Динамическая заметка и LLM** (T-003, T-004, T-005): обобщённый рендер,
   динамический промпт и валидация ответа, снимок шаблона в сервисе конспекта.
   Встроенный путь остаётся байт-в-байт прежним, старые тесты зелёные.
3. **Разбор описания** (T-006): один вызов LLM «текущий шаблон + текст →
   патч», валидация кандидата. Пока без Telegram-входа.
4. **Telegram-сценарий** (T-007, T-008): `/template`, FSM, показ, подтверждение,
   сброс, изоляция; обработчик ссылки применяет активный шаблон.
5. **Ошибки и сквозная проверка** (T-009, T-010): понятные сообщения и
   приватные логи, E2E текстового сценария, README. После этого инкремента
   текстовая версия спеки закрыта.
6. **Голосовой ввод** (T-011, T-012, бэклог): адаптер распознавания речи,
   необязательный конфиг, голосовое сообщение в том же сценарии.

Текущий инкремент — этапы 1–5 (T-001–T-010); голос — бэклог. Каждая задача
заканчивается зелёными `pytest -q` и `ruff check .` в `app/` и не ломает запуск
бота; встроенное поведение MVP доступно на любом шаге.

## Совместимость с MVP

- `parse_summary`, `VideoSummary` (прежние поля), `render_note(note)` по
  умолчанию, `note_filename`, frontmatter, allowlist, тексты ошибок и
  асинхронность не меняются.
- `create_router(service)` и `LinkHandler(service, allowed_user_ids=...)`
  остаются рабочими без новых аргументов.
- Все 371 прежний тест остаются зелёными; новые тесты не ходят в сеть и не
  требуют токенов. Внешние границы подменяются `httpx.MockTransport`,
  `FakeSession` и фейковыми адаптерами; E2E идёт через настоящие `Dispatcher`,
  обработчики, сервис и storage.

## Риски и проверки

- **Схема ответа LLM** — модель может вернуть старую или частичную схему:
  строгая валидация до модели заметки, тесты на пропуск/лишний/пустой раздел,
  повторы только на 429/5xx, `LLMError` без частичной заметки.
- **Prompt injection** — описание шаблона и тон передаются как данные,
  инструкции из них не выполняются; тест с «верни JSON без разделов» в тексте.
- **Совместимость** — двойной путь (встроенный/динамический) может разойтись:
  регрессионные тесты на промпт, рендер и E2E встроенного шаблона в каждой
  задаче.
- **Атомарность и изоляция** — путь только из `DATA_DIR`, user ID проверяется,
  запись через `os.replace`, тесты на повреждённый файл, чужой ID и
  параллельную запись.
- **Порядок роутеров и FSM** — ссылка во время ввода описания не должна тратить
  квоту; тест на отсутствие вызовов YouTube/LLM в этом состоянии.
- **Устаревшие кнопки** — повторный callback не сохраняет дважды; тест на
  stale callback и на перезапуск (кандидат не пережил, активный шаблон цел).
- **Приватность** — полный текст описания, тон и аудио не попадают в лог;
  тесты с `caplog` и секретами-ловушками.
- **Стоимость** — разбор шаблона один вызов LLM на изменение, генерация заметки
  остаётся одним вызовом; тест считает вызовы.
- **Оценка размера** — все задачи идут как M: они трогают несколько слоёв и
  тестовых файлов; для S-ярлыка здесь нет основания (см.
  `app/skills/size-forecast/SKILL.md`). При возврате ревью `ISSUES` учитывать
  отдельные FIX и REVIEW-2.
