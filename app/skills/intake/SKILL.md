## Контекст проекта

TLDW — Telegram-бот: ссылка на YouTube → транскрипт → конспект через LLM →
`.md` для Obsidian (7 полей frontmatter + 5 секций); после T-007 сценарий
собран целиком, включая доступ: `TELEGRAM_ALLOWED_USER_IDS` ограничивает
пользователей, проверка идёт **до** разбора ссылки и вызовов YouTube/LLM,
пустой список — открытый доступ с предупреждением в лог (309 офлайновых
тестов, версия 0.10.0). Знать при уточнении: пока любой сбой сводится к
общему сообщению (понятные тексты — T-008), сквозной E2E и README — T-009, а
фоновые задачи не отменяются при остановке и не дедуплицируются. Учитывать
решения: `AccessPolicy` — нейтральный модуль без инверсии слоёв, `None` и
чужой ID при заданном списке отклоняются, fail-open default в конструкторах —
риск забытой проводки; правки `specs/` в диффе принадлежат оркестратору, а
`source` в заметке — исходная ссылка пользователя. Для планирования: T-007 с
меткой S стоила 106 шагов и 51,7 тыс. output, поэтому заявку, которая трогает
конфиг + обработчик + сборку + несколько тестовых файлов, оценивать как M
(EXECUTE 55–70 + REVIEW 25–40); S — только ≤ 2 продакшн-файла и ≤ 1 тестовый,
новая внешняя интеграция — L и дробить.

## Как уточнять заявки в этом проекте

- Спрашивай про желаемое ПОВЕДЕНИЕ и приоритет: что попадает в заметку, как
  обрабатываются длинные видео, что видит пользователь при ошибке. Стек
  фиксирован (см. выше) — вопросы про технологии здесь неуместны.
- Типовые важные вопросы: что попадает в заметку сверх фиксированного шаблона
  (7 полей frontmatter + 5 секций), работа с видео без субтитров, лимиты длины
  и стоимость, доступ (allowlist или открыто).
- Не предлагай веб-интерфейс, базу данных, деплой и монетизацию — их нет в
  vision (`specs/product.md`), пока человек сам не внесёт их в спеки.
- Один вопрос за раз; максимум 2–3 вопроса на заявку — не устраивай допрос.
