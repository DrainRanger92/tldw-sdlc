## Контекст проекта

TLDW — Telegram-бот: ссылка на YouTube → транскрипт → конспект через LLM →
`.md` для Obsidian (7 полей frontmatter + 5 секций); после T-005 серверный
сценарий собран целиком: `SummaryService.process(url)` проверяет порог
длительности из конфига (дефолт 2 ч), склеивает транскрипт с таймкодами,
усекает его по границам сегментов с маркером, собирает заметку и атомарно
пишет файл в `DATA_DIR` — всё на фейковых адаптерах, 257 офлайновых тестов.
Осталось подключить это к Telegram: обработчик T-006, allowlist T-007,
понятные сообщения об ошибках T-008, E2E и README T-009; сам сервис
синхронный, поэтому обработчик обязан уводить его в `asyncio.to_thread`.
При уточнении полезно знать: шаблон заметки, порог длительности и лимит
транскрипта фиксированы в конфиге/ресурсах (менять их — отдельная заявка),
внешние вызовы только через адаптеры, секреты только из env/`.env`, а
`source` в заметке — исходная ссылка пользователя. Для планирования: задача
на композицию готовых контрактов — это M (60–100 шагов), задача с новой
внешней поверхностью (новая библиотека/API, отправка файлов, async-выход
наружу) — L, её дробить ещё на этапе заявки, прогноз 80–120 шагов.

(Эту секцию обновляет этап LEARN после каждого цикла: что появилось,
какие решения приняты. Свежий срез бэклога и памяти приходит в сообщении —
он всегда актуальнее этого текста.)

## Как уточнять заявки в этом проекте

- Спрашивай про желаемое ПОВЕДЕНИЕ и приоритет: что попадает в заметку, как
  обрабатываются длинные видео, что видит пользователь при ошибке. Стек
  фиксирован (см. выше) — вопросы про технологии здесь неуместны.
- Типовые важные вопросы: что попадает в заметку сверх фиксированного шаблона
  (7 полей frontmatter + 5 секций), работа с видео без субтитров, лимиты длины
  и стоимость, доступ (allowlist или открыто).
- Не предлагай веб-интерфейс, базу данных, деплой и монетизацию — их нет в
  vision (`specs/product.md`), пока человек сам не внесёт их в спеки.
- Один вопрос за раз; максимум 2–3 вопроса на заявку — не устраивай допрос.
