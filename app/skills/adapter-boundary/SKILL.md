# Граница внешнего HTTP-адаптера

Паттерн повторился трижды: T-003 (YouTube + yt-dlp), T-004 (LLM,
`chat/completions`) и T-011 (распознавание речи,
`audio/transcriptions`). Каждый раз адаптер получался похожим — модуль в
`tldw/adapters/`, настройки из `Settings`, `httpx` только внутри, typed
ошибки, `MockTransport` в тестах, — но каждый раз ревью находило одни и те
же дыры: `httpx.InvalidURL` мимо типизированной ошибки (T-004, T-011),
необязательные env, которые забыли синхронизировать с `.env.example`,
payload/URL в логе, `except Exception` в обработчике, маскирующий отказ.
Скил фиксирует рецепт, чтобы новый адаптер не повторял четвёртую копию.

## Когда применять

- Новая внешняя интеграция: HTTP API, библиотека-обёртка, распознавание
  речи, платёжный/почтовый сервис.
- Ревью любого файла в `app/tldw/adapters/` — пройдите по чек-листу ниже.
- Новая возможность поверх готового адаптера (как T-012 поверх
  `SpeechAdapter`) — использовать существующий адаптер, а не писать второй
  HTTP-клиент; см. скил `optional-boundary`.

## Рецепт

1. **Модуль и протокол.** Новый `tldw/adapters/<name>.py`; обработчики и
   сервисы не импортируют `httpx` (ADR-002). Публичный класс/фабрика
   (`from_settings`), `__all__`, реэкспорт в `adapters/__init__.py`.
   Синхронный вызов — вызывающий слой уводит в `asyncio.to_thread`.
2. **Настройки — только необязательные env.** Дефолты в `config.py`;
   `load_settings` работает без переменных; пустой ключ/модель = «не
   настроено», а не `ConfigError`. Обновить `OPTIONAL_ENV_VARS`,
   `ALL_ENV_VARS`, `.env.example`, README-таблицу и тест
   `test_env_example_lists_every_app_variable_without_secrets`.
   `Settings.repr` не должен показывать ключ.
3. **Валидация URL — целиком, через общий `config.validate_http_url`.**
   Не пишите третью проверку в адаптере: `validate_http_url(value, name=...)`
   проверяет схему, непустой host, порт 1–65535, IPv6, пробелы и `Cc`-символы
   и возвращает URL без завершающего `/`. Ошибка — `ConfigError` на старте
   `load_settings`; в конструкторе адаптера — та же функция (для тестов и
   прямых вызовов). Помнить: `httpx.InvalidURL` **не** наследник
   `httpx.HTTPError`.
4. **Таймаут и число попыток.** `httpx.Timeout(self.timeout)`; таймаут —
   конечное положительное число (проверять `math.isfinite`, не только
   `> 0`). Одна попытка по умолчанию; повторы — только если контракт
   явно идемпотентен и это отдельное решение (T-004: 429/5xx; T-011:
   повторов нет).
5. **Типизированные ошибки.** `<Name>Error(UserFacingError)` + подклассы
   (`NotConfigured`, `TooLong`, `Timeout`, `Provider`, `Response`).
   Сообщения — русские, без внутренних деталей; причина — в лог. Ловить:
   - `httpx.TimeoutException` → timeout;
   - `httpx.InvalidURL` **и** `httpx.HTTPError` → provider/network;
   - `response.status_code >= 400` → provider (не логировать тело);
   - `ValueError`/не-JSON/пустой текст → response.
   Создание клиента (`_make_client`) — внутри `try`, если оно может
   бросить.
6. **Приватность логов.** Не логировать payload, тело ответа, полный текст
   распознавания/транскрипт, URL с query и ключ. Можно: длительность,
   число байт/символов, код ответа, тип исключения. `__repr__` адаптера
   скрывает ключ. Тесты `caplog` проверяют обе стороны: payload **нет**, а
   служебные поля **есть**.
7. **Проверки до сети.** Лимит длительности/размера, `is_configured`,
   пустой вход — до `client.post`; тест утверждает `requests == []`.
   Порядок проверок фиксировать: в T-012 обработчик проверяет
   `is_configured` раньше лимита, иначе ненастроенный адаптер ответил бы
   «слишком длинное» (P3 T-011, закрыт в цикле 12).
8. **Тесты на `httpx.MockTransport`.** Минимум: успех (проверить URL,
   заголовок авторизации, multipart/JSON, таймаут в `request.extensions`),
   4xx/5xx, таймаут, сетевой сбой, битый/пустой ответ, отсутствие
   конфигурации, лимит, невалидный URL, `inf/nan` таймаута, `repr` без
   ключа, логи без payload. 40–60 кейсов — норма (T-011: 52). Сеть и
   реальные ключи не нужны (см. `offline-tests`).
9. **Гейты и документация.** `ruff check .`, полный `pytest` в обычной
   песочнице; README — переменные, лимит, приватность, fallback; CHANGELOG
   и версию ведёт оркестратор (см. `release-metadata`).

## Чек-лист ревью адаптера

- [ ] `httpx` не импортируется вне `adapters/`.
- [ ] Нет новых обязательных env; `.env.example`/`ALL_ENV_VARS`/README
      синхронны; `load_settings` работает без новых переменных.
- [ ] URL валидируется полностью (host/port), а не только префикс.
- [ ] `httpx.InvalidURL` и `HTTPError` обёрнуты в typed error; создание
      клиента внутри `try`.
- [ ] Таймаут конечный и положительный; число попыток соответствует
      контракту.
- [ ] Тяжёлый внешний вызов один на `fetch`: метаданные не запрашиваются
      вторым полным запросом (T-014: `FallbackVideo`).
- [ ] Каждый прямой импорт объявлен в `pyproject.toml`, даже если приходит
      транзитивно (P2 T-014: `requests`).
- [ ] Побочные записи библиотеки отключены или лежат в `DATA_DIR`
      (`cachedir: False` у yt-dlp).
- [ ] `status >= 400`, битый JSON, пустой текст → разные typed ошибки.
- [ ] Payload/тело/полный текст/ключ не в логе и не в `repr`.
- [ ] Лимит и `is_configured` проверяются до сети; порядок проверок
      осмыслен.
- [ ] Тесты покрывают успех, 4xx/5xx, таймаут, сетевой сбой, битый ответ,
      конфиг, лимит, битый URL, `inf/nan`; `MockTransport`, без `tmp_path`.
- [ ] `__all__`/`adapters/__init__.py`/README-дерево обновлены.
- [ ] `ruff` и полный `pytest` зелёные; в read-only ревьюер может прогнать
      файл без `tmp_path`.

## Анти-паттерны

- `except httpx.HTTPError` без `InvalidURL` — ошибка конфига вылетает
  сырым исключением (T-004 P1, T-011 P2).
- Проверять URL только `startswith("http://")` — пропускает `:bad`,
  пустой host, `https://[`.
- Логировать тело ответа/транскрипт/аудио «для отладки».
- Оборачивать всё в `except Exception` в обработчике — дыра остаётся
  невидимой для E2E.
- Делать ключ/модель обязательными — ломает текстовый сценарий.
- Повторять запрос по умолчанию — стоимость и маскировка ошибок.
- Тестировать только happy path и только валидный `base_url`.
- Импортировать `httpx` в сервисе/обработчике «на минутку».

## После T-012: адаптер не менялся, но границы уточнились

T-012 не создавала нового адаптера — она подключила `SpeechAdapter` к
Telegram-сценарию. Это лучший исход для скила: вместо четвёртой копии
HTTP-клиента появился один обработчик. Что подтвердилось и что осталось:

- **проверка `is_configured` в обработчике снимает двойной WARNING**
  (P3 T-011): адаптер не вызывается, его сообщение «не настроено»
  недостижимо; в обработчике — один текст и текстовый fallback. Правило:
  «не настроено» — решение вызывающего слоя, а не адаптера;
- **лимит длительности переехал в `config.py`** (`MAX_AUDIO_DURATION_SECONDS`),
  но адаптер оставил реэкспорт в `__all__`, а тесты импортировали из двух
  мест — это P3 (`shared-helpers`), **закрыто в T-015**: реэкспорт убран,
  единственный публичный путь — `tldw.config`. Перенос константы = удалить
  старый путь импорта или явно объявить его deprecated;
- **`httpx.InvalidURL` в `SpeechAdapter` не закрыт** (P2 T-011): T-012 его
  не касалась, а конфиг по-прежнему проверяет только схему. Каждый новый
  адаптер обязан ловить `InvalidURL` в `_make_client`/`try` — иначе долг
  переезжает из цикла в цикл;
- **`media_type` из Telegram не передаётся** — обработчик использует
  дефолт адаптера, поэтому P3 о CRLF в `media_type` остаётся
  теоретическим. Если будущая задача начнёт передавать тип из апдейта,
  сначала ограничить набор MIME-типов.

## Цикл 13: `InvalidURL` закрыт в LLM и речи, правило стало кодом

T-013 выполнила пункты 3–5 рецепта в обоих HTTP-адаптерах:

- `config.validate_http_url` — одна проверка для `LLM_BASE_URL` и
  `SPEECH_BASE_URL` (схема, host, порт, IPv6, пробелы/`Cc`), `ConfigError`
  на старте, значение не попадает в сообщение;
- `LLMClient` и `SpeechAdapter` оборачивают **и** `_make_client()`, **и**
  `client.post()`; `httpx.InvalidURL`/`ValueError` → typed provider error;
- отсутствие ресурса промпта/маркера → `LLMConfigError`, а не `RuntimeError`;
- `media_type` ограничен `ALLOWED_AUDIO_MEDIA_TYPES` (без CRLF/пробелов,
  регистр нормализуется);
- тесты: 8+ битых URL × два адаптера на уровне конфига, `InvalidURL`/
  `ValueError` на уровне запроса, отсутствующий ресурс, пустой транскрипт.

**Что осталось и что проверить в новом адаптере:**

- `except (InvalidURL, ValueError)` вокруг `post` широк: `ValueError`
  сериализации payload тоже станет «ошибкой провайдера». Сужайте или
  комментируйте;
- `_media_type` на неизвестный MIME кидает plain `ValueError` — при приёме
  типа из Telegram будет `MESSAGE_UNEXPECTED`; нужен безопасный фолбэк;
- **YouTube-адаптер мигрирован в цикле 14** (T-014): таймаут сессии, один
  `_extract_info`, приоритет ошибок, `TypeError` на битом ответе, кэш yt-dlp
  — см. раздел «Цикл 14» ниже;
- новый адаптер обязан **переиспользовать** `validate_http_url` и обёртки,
  а не писать четвёртую копию. Если это невозможно (другой протокол) —
  объясните в отчёте, почему.

## Цикл 14: не-httpx адаптер — таймаут через сессию, один fetch и зависимости

T-014 закрыла последний P1-раздел адаптеров на `youtube-transcript-api` +
`yt-dlp`. Это не httpx-адаптер, и рецепт пришлось расширить:

- **Таймаут, если библиотека его не принимает.** `youtube-transcript-api`
  1.x не имеет параметра `timeout` в `fetch`, но принимает готовую сессию
  `http_client`. Решение — `_TimeoutSession(requests.Session)`, которая
  подставляет `timeout` в каждый `request`; значение валидируется
  (`math.isfinite`, > 0) и по умолчанию 10 с. Не оборачивайте вызов в
  `to_thread` «с таймаутом»: поток останется занят зависшим запросом.
- **Один дорогой вызов на `fetch`.** Внутренний контракт fallback:
  `FallbackClient.fetch(video_id) -> FallbackVideo` (транскрипт **и**
  метаданные из одного `_extract_info`). Если библиотека отдаёт несколько
  полезных полей за один запрос, не делайте второй запрос «за метаданными».
  Меняя такой контракт, обновите ADR и скилы, которые его описывают
  (P3 T-014: ADR-004 и `offline-tests` отстали).
- **Приоритет ошибок — данные, а не порядок `except`.** `_transcript_error`
  возвращает пару «итоговая ошибка + причина»; `raise final from cause`
  указывает на источник, определивший итог. Проверяйте матрицу сочетаний
  primary/fallback и `__cause__`, а не один сценарий.
- **Нормализация чужого ответа — на границе.** `_segments_from_fetched`
  принимает итерацию объектов со строковым `text` и числами
  `start`/`duration`; `None`, старый dict-формат, строка, не-итерация,
  битые числа → typed `YouTubeNetworkError`. Ловите **все** исключения
  итерации, а не только `TypeError` (P3 T-014), иначе сырое исключение
  выйдет наружу.
- **Ошибки библиотеки различайте по признаку, а не по классу.** У `yt-dlp`
  нет отдельных классов private/unavailable — маркеры в тексте
  `DownloadError` дают `VideoUnavailableError`, остальные —
  `YouTubeNetworkError`; текст исключения в лог не пишется.
- **Побочные записи отключайте.** `cachedir: False` у `yt-dlp`, иначе кэш
  уходит в `~/.cache` вне `DATA_DIR`; тест должен проверять отсутствие
  записи при подменённых `XDG_CACHE_HOME`/`HOME`.
- **Прямой импорт = объявленная зависимость.** `requests` пришёл
  транзитивно через `youtube-transcript-api`, адаптер импортирует его
  напрямую. Ревью записало **P2**: объявить `requests>=2,<3` в
  `pyproject.toml` (T-018) или зафиксировать транзитивность тестом. Правило:
  если модуль импортирует пакет, которого нет в `pyproject.toml`, — это
  долг упаковки, даже если гейты зелёные.
- **Тесты — на фейковой библиотечной границе.** 92 кейса в
  `test_youtube_adapter.py`: подмена `YoutubeDL` фейком, записывающий
  transport для проверки `send(timeout=...)`, счётчик `extract_info`,
  матрица 9 сочетаний primary/fallback. `FakeYoutubeDL.instances` не должен
  быть мутабельным классовым состоянием (P3 T-014) — сбрасывайте его
  фикстурой, а не только хелпером установки.

См. `adr-017-typed-error-contract-url-validation.md` и
`t013-debt-audit.md`.
