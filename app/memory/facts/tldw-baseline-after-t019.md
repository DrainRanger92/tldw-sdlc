# Базовая линия TLDW после T-019: FIX-2 проверен, набор 1151 тест

Дата: 2026-11-27. Срез после T-019 (цикл 17). Версия в рабочей копии —
**0.21.0**; оркестратор поднимет её при коммите (ожидается 0.22.0). Это
текущее состояние `app/` для следующего цикла: бэклог 003 — **T-017** и
**T-018**, долг ≈62. T-019 не добавляла возможностей: одна продакшн-правка
(`errors.py`, +8/−4) и 7 тестов.

## Что умеет приложение

- **Telegram-сценарий:** ссылка на YouTube или голосовое описание ≤ 60 с →
  транскрипт → конспект через LLM → `.md` для Obsidian; `/template` и
  кнопка «Шаблон» (1–12 разделов, тон 0–1000, разбор текста через LLM,
  кандидат сохраняется только после «Сохранить»); голос идёт тем же путём,
  что текст; allowlist по user ID, понятные ошибки, README и E2E.
- **Логи:** `SanitizingFilter` на root и обработчиках, `sanitize_log_text`
  по месту; URL сводится к `схема://host`, секреты скрываются по формам,
  `max_tokens`/`MAX_TOKENS`/`MAX_OUTPUT_TOKENS`/`input_tokens`/`tokens` и
  **`tokenizer`/`TOKENIZERS_PARALLELISM` остаются видимыми** (исключение
  `TOKEN(?!S|IZER)` добавлено в T-019); известные ошибки поднимаются до
  порога `LOG_LEVEL` (осознанный компромисс ADR-022).
- **Доступ и ссылка:** fail-open при забытом allowlist (`AccessPolicy.open`
  + `WARNING`, лимит повторных отказов), дедупликация по
  `(chat_id, user_id, video_id or url)`, `MAX_CONCURRENT_LINKS = 2`
  (семафор вокруг `process`, очередь не ограничена — T-017), отмена
  фоновых задач при остановке, `title`/`channel`/`</transcript>` как данные.
- **Проверенное качество:** FIX-2 T-016 (29 правок, +9 тестов) проверен
  независимо; найден и исправлен регресс `tokenizer`; **1151 офлайновый
  тест** в 29 модулях (+7), `ruff check .` чисто; `pytest` — 3,9 с.

## Что осталось

- **T-017** — единый источник помощников, лимитов и валидаций; сюда же
  переданы дубли обёрток «лог + ответ», `_log_denied`/`DenialLogLimiter` и
  `MAX_CONCURRENT_LINKS` в `Settings`. **Помечена `M`, но трогает ≥ 9
  модулей — по ADR-023 это L**: дробить до EXECUTE, иначе 400–550 шагов.
- **T-018** — тесты, README и упаковка: покрытие P1 E2E, `requests`,
  `BASE_ENV`, общие тестовые помощники, флаки, `MAX_PATCH_OUTPUT_TOKENS`,
  ленивые импорты. Ближе к M4 (170–235 шагов цикла).
- Долг **≈62** не изменился: T-019 ничего не закрывала и не добавляла.
- **Остаточные риски T-019** (не задачи): `_close_application` ловит
  `Exception`, а не `BaseException` (намеренно); хвост `[A-Za-z0-9_]*`
  скрывает теоретические `TOKENIZE_DATA`/`TOKEN_USAGE`/`token_count`, в
  коде таких форм нет; новый тест дедупликации дублирует существующий —
  консолидация в T-018; критерий `_visible_level` в `tasks.md` сформулирован
  буквально неверно (компромисс ADR-022), код не трогать; в описании T-019
  был указан не тот файл — процессный долг ANALYZE.
- **Ревью T-019** — `APPROVE` с 4 неблокирующими пунктами, FIX не было;
  полный `pytest` у ревьюера не пошёл (read-only), `test_errors.py` —
  50 passed; LEARN перепроверил 1151.
