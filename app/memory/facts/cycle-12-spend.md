# Расход цикла 12: одиночная M4 — голосовой ввод (T-012)

Дата: 2026-11-27. Цикл 12 — второй цикл после батча 002 и вторая одиночная
задача из бэклога. «Текущий инкремент» снова был пуст: `pull_from_backlog`
поднял одну T-012 («Голосовой ввод шаблона в Telegram и документация»,
метка **M** без подкласса). ANALYZE/PLAN не запускались. Цикл состоял из
двух сессий — EXECUTE и REVIEW; ревью дало `VERDICT: APPROVE` с первой

## Откуда цифры

`journal.jsonl` содержит циклы 1–11; цикла 12 в нём ещё нет (последняя
строка — цикл 11, `7e81432`). Расход восстановлен по кэшу DSH-сессий
(`session_projcache/sessions/*.json`, `tokenUsage.totals`) и журналам
`session.v4.jsonl.zstd` (`step/start`, `tool/call`, `tool/result`,
`user/message`) по процедуре `app/skills/cycle-accounting/SKILL.md`.
Пакета `zstandard` по-прежнему нет: zstd распаковывался через `libzstd.so.1`
и `ctypes`, **но в этот раз файл состоял из нескольких кадров**, и
однокадровый декодер вернул только заголовок сессии (981 строка вместо
одной). Подробность — в скиле `cycle-accounting`. Сессия LEARN (текущая) в
таблицу не входит.

## Сравнение с оценкой

T-012 помечена **M**, без подкласса и без прогноза. Прогноз, записанный
памятью цикла 11 (по правилу подклассов), — **M3:
`EXECUTE 80–115 + REVIEW 25–40 = 105–155` шагов, 65–95 тыс. output**
(`estimate-backlog-label-stale.md`).

- **EXECUTE 134** — выше верхней границы M3 (115) на **16,5 %**;
  **REVIEW 63** — выше вилки 25–40 на **57,5 %**; итог **197** — выше
  155 на **27 %**; output 135,6 тыс. — выше 95 тыс. на **43 %**;
- **плоская M** (`55–70 + 25–40 = 80–110`) промахнулась бы в
  **1,79–2,46 раза**; один EXECUTE (134 против 55–70) — в 1,91–2,44 раза;
- класс угадан (M3+), но **потолок M3 сломан**: это первый замер, который
  не влезает ни в M3, ни в «M3 + REVIEW»; по разбору — `M4`
  (`EXECUTE 120–160 + REVIEW 50–75 = 170–235`, 100–140 тыс. output);
  см. `estimate-m3-ceiling-broken.md`;
- по сравнению с циклом 11 **на задачу**: 197 против 125 шагов (+58 %),
  135,6 против 81,3 тыс. output (+67 %), 26,58 против 9,87 млн токенов
  (в 2,7 раза), 34,9 против 19,6 мин (+78 %). Причина не в новом внешнем
  контракте (адаптер уже был), а в **ширине проверки**: два новых
  тестовых файла, E2E, README и закрытие трёх долгов T-011 по пути.

## Куда ушли шаги

- **Тестовый каркас и два новых файла тестов.** Два новых файла
  (873 строки: 516 + 357) плюс 152 строки в `support.py` — это 66 %
  diffstat и основные 134 шага. Разработчик 12 раз правил `support.py`, чтобы
  добавить фейковую границу речи, аудио в `FakeSession` и поле `speech`
  в `TemplateStand`; это третья задача подряд (T-009, T-010, T-012), где
  общий каркас — главная статья расхода (`tests-and-docs-cost-like-code.md`).
- **Обработчик и проводка.** `handle_voice` — 280 строк: allowlist,
  состояние, `is_configured`, лимит, скачивание в `BytesIO`, `to_thread`,
  общий `_present_description`; плюс `bootstrap`/`router`/`config` и
  перенос константы. 10 правок в `template.py`, 5 — в `config.py`,
  3 — в `bootstrap.py`.
- **Ревью — широкое, но недорогое по времени.** 63 шага на 16 файлов и
  1547 строк: 14 git-вызовов (2 упали на окружении), 11 запусков pytest
  (703/927 в read-only), `ruff` чисто, проверка критериев по пунктам,
  `specs/`-артефакт, `job_output` для фоновых прогонов. Output 36,5 тыс. —
  37 % output разработчика при 47 % шагов; ревью больше не «дороже
  разработчика на шаг» (579 против 1 018 у T-011), потому что проверка
  шла по готовым тестам.
- **Git-окружение — самый чистый цикл.** Разработчик с первого вызова
  использовал `git_ws`-обёртку: 9 git-вызовов, **0 падений**. Ревьюер
  начал с обычного `git -C /workspace …` (2 падения:
  `GIT_CONFIG_KEY_0`, затем `dubious ownership`) и перешёл на
  `export GIT_CONFIG_KEY_0=safe.directory`; итого **2 падения из 23**
  git-вызовов — лучше циклов 10 (18/85) и 11 (4/12), см.
  `git-env-broken-in-dsh.md`.

## Что это значит для следующего цикла

- **Одиночная задача из бэклога — уже не аномалия, а режим:** две подряд
  (T-011, T-012) стоили 125 и 197 шагов. ADR-014 разрешает одиночный
  инкремент для риска, но вторая подряд задача показала его настоящую
  цену — 2,2 × батча на задачу; см. `single-task-pull-from-backlog.md`.
- **M3 — не последний подкласс.** Комбинация «новый медиа-путь + два
  тестовых файла + E2E + README + закрытие долгов» даёт 134 шага
  EXECUTE; её надо либо дробить (обработчик+юнит-тесты / E2E+README), либо
  оценивать как M4 (`estimate-m3-ceiling-broken.md`).
- **Ревью одиночной задачи считать по диффу, а не по шагам задачи:**
  25–40 шагов — для 2–3 тестовых файлов; 16 файлов и 1,5 тыс. строк —
  55–75 шагов, даже если задача одна.
- **Долг почти не изменился:** 7 новых P3, закрыто 3 группы T-011
  (handoff, `inf/nan`, порядок проверок, двойной WARNING) — 83 → ≈87;
  P1 T-004/T-005 и P2 `InvalidURL` в речи по-прежнему открыты
  (`t012-review-issues.md`, `review-debt-accumulates.md`).
- **Бэклог пуст.** После T-012 в `specs/002-user-note-templates/tasks.md`
  нет ни одной pending-задачи; следующий инкремент нужно планировать
  (долг ревью — первый кандидат), иначе `pull_from_backlog` снова не
  найдёт работу.
