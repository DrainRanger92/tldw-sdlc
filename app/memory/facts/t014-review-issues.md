# Замечания ревью T-014: `APPROVE` с одним P2 и шестью P3

Дата: 2026-11-27. Ревью T-014 («Надёжность YouTube-адаптера: таймаут, один
запрос метаданных, приоритет ошибок и кэш») завершилось
`VERDICT: APPROVE` с первой итерации: все 8 критериев закрыты, дефектов
корректности не найдено, 1056 тестов у разработчика, 797 из 1056 в read-only,
0 failed, `ruff check .` чисто. FIX не запускался, поэтому всё ниже осталось
в коде/документации, кроме отмеченного «закрыто в LEARN».

Ревью — **62 шага, 49,3 тыс. output** на 5 файлов и +753/−105; дороже
EXECUTE (54 шага) по шагам, потому что проверяло 9 критериев, матрицу
сочетаний и утверждения о двух сторонних библиотеках (7 `web_fetch`,
1 `web_search`). Подробный расход — `cycle-14-spend.md`.

## P2 — качество/упаковка

1. **`requests` импортируется напрямую, но не объявлен в
   `app/pyproject.toml`.** `adapters/youtube.py:40` делает
   `from requests import Response, Session` и `requests.exceptions.Timeout`;
   пакет приходит транзитивно через `youtube-transcript-api 1.2.x` (там он
   жёсткая зависимость), поэтому «новых зависимостей» формально нет и гейты
   зелёные. Но если библиотека сменит HTTP-клиент в пределах `<2`, импорт
   сломается без изменения нашего кода. Ревьюер проверил метаданные
   `youtube-transcript-api` и `_api.py` (`http_client` есть с 1.2.0) через
   `web_fetch`. **Статус: открыт → T-018** (упаковка/зависимости: объявить
   `requests>=2,<3` или зафиксировать транзитивность тестом).

## P3 — корректность и границы

2. **`_segments_from_fetched` (`youtube.py:541-546`) ловит только
   `TypeError`** при `list(fetched)`. Если «битый» объект бросит из
   `__iter__` `AttributeError`/`RuntimeError`, сырое исключение выйдет из
   `TranscriptApiClient.fetch`, хотя нормализация обещает
   `YouTubeNetworkError`. Для полноты границы ловить `Exception` (как в
   остальных местах) или явно назвать допустимые типы. **Открыт → T-018.**

3. **`except Timeout` — мёртвая ветка.** В `TranscriptApiClient.fetch`
   (`youtube.py:350-351`) `except Timeout` полностью перекрывается следующим
   `except Exception` с тем же маппингом в `YouTubeNetworkError`. Тест
   `test_transcript_api_client_maps_timeout_to_network_error` дублирует кейс
   `session-timeout` из параметризованного теста. Оставить одну ветку и один
   тест. **Открыт → T-018.**

4. **`_timeout_seconds` дублирует `_seconds`.** `youtube.py:580-588` и
   `:690-698` — те же проверки `bool`/типа/`isfinite`, отличаются только
   `> 0` против `< 0`. Один помощник с параметром границы; иначе следующая
   правка поправит одну копию. **Открыт → T-017** (единый источник
   помощников/валидаций).

5. **Покрытие `socket_timeout` уже, чем `timeout`.** Для `timeout`
   проверены 0/−1/inf/nan/str/bool/None, для `socket_timeout` — только
   0/inf/str; `None`, `bool`, отрицательное не покрыты. **Открыт → T-018**
   (полнота тестов).

6. **`FakeYoutubeDL.instances` — мутабельное состояние класса.**
   Сбрасывается только в `install_fake_ytdlp`; если новый тест забудет
   хелпер, экземпляры утекут между кейсами (флаки). **Открыт → T-018**
   (флаки/тестовые дубли).

## P3 — документация, закрыто в LEARN

7. **Документация отстала от нового внутреннего контракта.** Ревьюер нашёл
   три расхождения:

   - `memory/MEMORY.md` не содержит строки для нового

   **Закрыто в LEARN:** ADR-004 получил статус «уточнён ADR-019» и актуальное
   описание `fetch`/приоритета; `offline-tests` переведён на

   скилы, которые его описывают**, иначе ревьюер найдёт расхождение, а
