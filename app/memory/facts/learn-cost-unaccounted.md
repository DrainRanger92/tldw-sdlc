# LEARN стоит как половина задачи и в бюджет цикла не входит

Дата: 2026-11-26. Все отчёты `cycle-0N-spend.md` считают расход «до LEARN»:
EXECUTE + REVIEW. Ретроспектива идёт отдельной сессией и в эти цифры не
попадает, хотя по шагам и output она сопоставима с выполненной задачей.

## Замеры

| Цикл | Задача | EXECUTE + REVIEW (шаги / output) | LEARN (шаги / output) | LEARN к задаче |
|---|---|---:|---:|---:|
| 1 | T-001 | 81 / 73 538 | 51 / 50 794 | 63 % шагов, 69 % output |
| 2 | T-002 | 53 / 56 770 | 60 / 52 715 | 113 % шагов, 93 % output |
| 3 | T-003 | 89 / 94 106 | 67 / 64 309 | 75 % шагов, 68 % output |
| 4 | T-004 | 100 / 113 372 | 117 / 70 300 | 117 % шагов, 62 % output |
| 5 | T-005 | 94 / 79 188 | ≥ 80 / ≥ 52 847 (на момент замера, идёт) | ≥ 85 % шагов |

Полный цикл 4 (с ретроспективой) — **217 шагов и 183,7 тыс. output**: в 2,2
раза больше шагов и в 1,6 раза больше output, чем показывает
`cycle-04-spend.md`. Токенов в LEARN тоже много: 3,4–11,2 млн cache read,
потому что агент перечитывает всю память, скилы, спеки и диффы.

## Почему это важно

- **Прогнозы и калибровка считают только задачу.** Если планировать цикл,
  нужно прибавлять LEARN: 50–120 шагов и 50–70 тыс. output, то есть почти
  вторую задачу. Иначе «стоимость инкремента» занижена вдвое.
- **LEARN растёт вместе с памятью.** 51 → 60 → 67 → 117 шагов за циклы 1–4:
  чем больше фактов и скилов, тем дороже их прочитать и обновить. Без
  ограничения на объём памяти ретроспектива будет дорожать каждый цикл.
- **Часть LEARN — это процедура, а не анализ.** Восстановление расхода по
  кэшу сессий каждый раз выяснялось заново; вынесено в скил
  `cycle-accounting`. Обновление индекса `MEMORY.md` и «Контекста проекта» —
  механическая работа, её стоит делать один раз и по шаблону.
- **Дорогая ретроспектива не обязательно полезнее.** Цикл 4 дал 117 шагов и
  9 обновлённых артефактов; ценность в основном в 4 новых фактах и 2
  скилах. Остальное — переписывание существующих файлов.

## Что делать

- В отчёте цикла писать две цифры: «до LEARN» и «всего с LEARN»; вторую — в
  отчётах оркестратора и в сравнении с прогнозом.
- Бюджет LEARN: **60–100 шагов и 50–70 тыс. output** на цикл; если выходит
  больше — сокращать число артефактов, а не глубину анализа.
- Держать память компактной: один факт = одна тема, обновлять существующий
  файл вместо нового, индекс — одна строка на файл. Раздувание памяти
  напрямую увеличивает стоимость следующего LEARN.
- Не переписывать файл целиком, если меняется абзац: точечные правки дешевле
  и меньше ломают историю (в цикле 5 так и делалось).
- Скилы, которые снимают процедурную работу (замер, git, ревью), окупаются:
  `cycle-accounting` убирает повторную разведку кэша сессий.

Связанные факты: `cycle-05-spend.md`, `cycle-04-spend.md`,
`estimate-forecast-underestimates.md`.
