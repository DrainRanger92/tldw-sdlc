# Замечания ревью T-009, оставшиеся в коде

Дата: 2026-11-26. Ревью T-009 прошло два раунда: первый — `ISSUES` (2 P2,
5 групп P3), после FIX — `APPROVE` с 3 P3 и одной информационной заметкой.
Закрыто в цикле 5 групп; в коде осталось три неблокирующих пункта и один
процессный, плюс **непокрытый P1-долг T-004/T-005**.

## Что нашёл первый проход (`ISSUES`)

1. **P2 — handoff.** `git add -N` не выполнен: diffstat показывал 3 файла и
   21/69 строк, а реальные новинки T-009 (`README.md` 156, `test_e2e.py` 386
   на момент ревью, `test_readme.py` 73, `support.py` 72 ≈ 687 строк) были
   untracked. Коммит только tracked-части сломал бы `test_link_handler.py`
   (импорт `support` без модуля). **Закрыто в FIX** (`git add -N app/`).
2. **P2 — дублирование тестового каркаса.** `test_e2e.py` завёл свои
   `Harness`/`make_harness`/`run_scenario`, `FakeYouTube`/`FakeLLM`,
   `make_video`/`make_summary`, хотя те же элементы были в
   `test_link_handler.py`, а `tests/support.py` создан в этом же изменении
   ровно для общего каркаса. ≈100 дублированных строк. **Закрыто в FIX**:
   каркас и билдеры перенесены в `support.py`, оба теста импортируют их.
3. **P3 — избыточные проверки в e2e.** Наличие и порядок пяти секций уже
   проверялись через `body.index(SECTION_HEADINGS)`, а строки 314–316
   повторяли те же `in body`, причём `SECTION_FOLLOW_UPS` — дважды.
   **Закрыто в FIX** (повторный цикл удалён).
4. **P3 — критерий «нет секретов в коде и тестах» не проверялся.**
   `test_readme.py` сканировал только README; код и тесты ничем не были
   защищены. Смежно: `test_readme_lists_every_env_var` в цикле по каждой
   переменной проверял один и тот же инвариант `.env.example` (тавтология),
   а проверка ручного сценария цеплялась за слова «frontmatter»/«секций» —
   тест ломался бы от переформулировки, а не от регресса. **Закрыто в FIX**:
   сканер по `app/**/*.py` с allow-list фиктивных значений и проверкой
   мутацией; инвариант `.env.example` вынесен в отдельный тест; проверки
   переведены на `FRONTMATTER_KEYS` и `SECTION_HEADINGS`.
5. **P3 — граница задачи.** `specs/001-mvp/tasks.md` (+17/−17) правится в
   задаче типа `app`: T-009 переставлен выше `## Бэклог`. Статусы и состав
   `tasks.md` — зона оркестратора. **Не менялось:** FIX оставил правку как
   чужую (в цикле 8 её, наоборот, откатили; см. `review-diff-untracked.md`).
6. **P3 — метаданные версии.** `tldw/__init__.py` 0.12.0 → 0.13.0 не в
   критериях T-009; версией владеет VERSION-стадия. Сейчас это чинит
   рассинхрон HEAD (`test_packaging` зелёный), но после VERSION-стадии HEAD
   снова станет красным; записи о T-009 в CHANGELOG нет. **Не менялось**
   (осознанно, см. `version-changelog-two-authors.md`).
7. **P3 — мелкие шероховатости.** `date.today()` в e2e считался после
   прогона (окно флака на полуночи); фиктивный токен дублировался трижды
   (`conftest.py`, `support.py`, `test_errors.py`); новые файлы имели права
   600 против 644. **Закрыто в FIX**: дата проверяется по обоим дням,
   токен берётся из `support.FAKE_BOT_TOKEN`, права 644.

## Что осталось после второго прохода

1. **P3 — README проверяется неполно.** `test_readme.py` сверяет точные
   тексты только для `MESSAGE_ACCEPTED`, `MESSAGE_PROCESSING`, `MESSAGE_DONE`;
   негативные сообщения в README даны сокращённо с «…». README может
   разойтись с `MESSAGE_NO_TRANSCRIPT`, `MESSAGE_VIDEO_TOO_LONG`,
   `MESSAGE_ACCESS_DENIED`, `MESSAGE_LLM_UNAVAILABLE`. Рекомендация —
   параметризовать проверку по этим константам.
2. **P3 — неточная формулировка README.** «При ошибке заметка не создаётся:
   ни `.md`, ни временных файлов» верно только для ошибок **до сохранения**;
   при сбое отправки документа после `save_note` файл уже лежит в `DATA_DIR`.
   Стоит уточнить «при ошибках обработки до сохранения».
3. **P3 — версия вне критериев** (`tldw/__init__.py` 0.13.0): оставлено
   осознанно, но после VERSION-стадии рассинхрон вернётся.
4. **Информационно — правка `specs/tasks.md`** в диффе: перенос T-009 из
   бэклога, критерии и статус не менялись, защищённые пути не затронуты.
5. **Не отмечено ревью, но важно: P1-долг T-004/T-005 не покрыт E2E.**
   `test_e2e.py` проверяет чужой ID, нет субтитров, слишком длинное видео и
   `LLMError`, но **не** проверяет пустой транскрипт и
   `InvalidURL`/`RuntimeError`. Оба P1 остаются открытыми с циклов 4–5, а
   сквозной сценарий — единственное место, где они проявились бы как
   «общее сообщение вместо своего текста». Долг по-прежнему невидим для
   тестов и ревью (см. `review-debt-accumulates.md`).

## Урок

- Ревью T-009 не нашло ни одного дефекта **поведения**: продакшн-код не
  менялся. Все P2 — про **процесс и тестовую обвязку** (handoff и
  дублирование каркаса). Это новый класс `ISSUES`: раньше возврат ревью
  означал реальный дефект, теперь — «работа сделана, но плохо оформлена».
  Готовить тестовую задачу к ревью нужно так же тщательно, как кодовую:
  `git add -N` до diffstat и общий каркас до написания E2E.
- Второй проход снова перепроверял исправления вручную и стоил 60 шагов:
  из 88 шагов ревью 60 пришлись на второй раунд. См.
  `review-fix-round-cost.md`.
