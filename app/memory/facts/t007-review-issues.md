# Замечания ревью T-007, оставшиеся в коде

Дата: 2026-11-26. Ревью T-007 (allowlist) дало `APPROVE` с первой итерации.
Все 5 критериев приёмки выполнены. Ревьюер выписал 8 пунктов: 6 по коду и
процессу (P2–P3) и 2 заметки (память и ограничение read-only). P1 среди них
нет, но P1-долг T-004/T-005 остаётся открытым — T-007 его не касался.

## P2 — процесс и безопасность по умолчанию

1. **Fail-open по умолчанию.** `create_router(..., allowed_user_ids=())` и
   `LinkHandler(..., allowed_user_ids=())` открывают доступ всем, если
   вызывающий забудет передать список. `bootstrap` передаёт явно, но
   надёжнее сделать аргумент обязательным или передавать готовый
   `AccessPolicy`. Сейчас ошибка проводки не падает, а молча открывает бота.
2. **Отказ без защиты и без ограничения частоты.** `await message.answer(
   MESSAGE_ACCESS_DENIED)` не обёрнут: при ошибке Telegram исключение уйдёт
   из обработчика в aiogram. `_log_denied` пишет WARNING на каждое сообщение
   чужого пользователя — спам-бот зальёт лог. Оба пункта в духе
   существующего кода и заявлены в T-008.
3. **Граница `app/`.** В дифф попала правка `specs/001-mvp/tasks.md` —
   перенос заголовка `## Бэклог` ниже T-007 (статусы не менялись). Это тот
   же паттерн, что в цикле 6: формально дифф выходит за `app/`, но правка
   оркестратора. Защищённые пути не затронуты.

## P3 — качество и дублирование

4. **Дедупликация ID продублирована.** `config._parse_allowed_user_ids`
   убирает повторы с сохранением порядка, и `AccessPolicy.__post_init__`
   делает то же самое. Два источника истины для одного правила;
   `AccessPolicy.is_open` используется только тестами.
5. **Хрупкие проверки логов.** В `test_bootstrap` проверки `warnings == []` /
   `warnings[0]` смотрят на все WARNING-записи, а не на
   `record.name == "tldw.access"` — тест сломается при любом предупреждении
   сторонней библиотеки на сборке.
6. **CHANGELOG: версия в записи не та.** Запись «0.9.0 — цикл 6» содержит
   строку «`tldw.__version__` синхронизирован с версией пакета», хотя
   синхронизация (0.9.0 → 0.10.0) сделана в этом цикле. Сам бамп корректен:
   `test_packaging` (сверка с `pyproject.toml`) проходит.

## Что ревью подтвердило хорошего

- Проверка доступа стоит **первой строкой** `handle_message` — до
  `extract_first_url` и до создания фоновой задачи; тест
  `test_access_is_checked_before_link_parsing` и ручной прогон это
  подтверждают.
- Чужой ID получает только `MESSAGE_ACCESS_DENIED`, `service.calls == []`;
  запрос не тратит квоту YouTube/LLM.
- Пустой allowlist пропускает всех и пишет предупреждение при сборке
  приложения; поведение покрыто на уровне политики, старта и обработчика.
- Некорректный allowlist даёт `ConfigError` без эха значения; CLI
  возвращает `EXIT_CONFIG_ERROR` без traceback, бот не стартует.
- `AccessPolicy` — нейтральный модуль без импортов `handlers`/`services`/
  `adapters` (ADR-002); 15 кейсов в `test_access.py`, полный набор 309.
- Секретов, `print`, `TODO` в новом коде нет; защищённые пути не затронуты.
