# Замечания ревью T-006, оставшиеся в коде

Дата: 2026-11-26. Ревью T-006 (Telegram-обработчик) дало `APPROVE` с первой
итерации и 9 пунктов: 1 P2 (процесс) и 8 P3/P4. Критерии приёмки — все 5
выполнены; замечания в код не внесены: LEARN код не меняет. Ревьюер отдельно
проверил, что P1-долг прошлых циклов не закрыт (см. ниже).

## P2 — процесс: diffstat не содержал основной код

1. **`link.py` и `test_link_handler.py` были untracked на момент ревью.**
   В промпте ревью был `git diff --stat` на 9 файлов и 109 строк, а реальный
   объём — ~721 строка: двух главных файлов (169 + 443) в диффе не было.
   Ревьюер сам увидел `??` в `git status` и прочитал их, поэтому вердикт
   корректен. Но если бы коммит собирал только отслеживаемые файлы,
   `handlers/__init__.py` импортировал бы несуществующий модуль →
   `ImportError` при старте. Оркестратор коммитит `git add -A`, так что код
   не потерялся; неполным было доказательство на ревью. Это регрессия
   процесса `git add -N` (см. `review-diff-untracked.md`).

## P3 — качество и поведение

2. **Нет левой границы у `_LINK_RE`.** `link.py:54-58`: шаблон
   `(?:[a-z0-9-]+\.)*(?:youtube\.com|…)` совпадает внутри
   `notyoutube.com/watch?v=x` и возвращает `youtube.com/watch?v=x` — ссылка
   уйдёт в адаптер и даст общий сбой. Нужна граница вида `(?<![a-z0-9.-])`
   или `\b` с проверкой предыдущего символа.
3. **URL целиком попадает в лог ошибки.** `link.py:139`:
   `log.exception("Не удалось обработать ссылку %s", url)` — query-строка
   произвольного домена может содержать токены/персональные данные, а
   T-008 требует «логи без секретов». Безопаснее логировать host или
   усечённый URL; это же требование записано в `spec.md` (приватность).
4. **Фоновые задачи не отменяются при остановке.** `Application.close()`
   (`bootstrap.py:38-40`) закрывает только сессию бота: задача в полёте может
   писать «готово» в уже закрытую сессию, а заметка — потеряться в середине
   отправки. `LinkHandler.wait_idle()` в проде не вызывается — это тестовый
   шов (задокументировано в `link.py:91-93`, но долг остаётся).
5. **Нет ограничения параллелизма и дедупликации.** Каждое сообщение
   порождает задачу без лимита; повторная ссылка тратит квоту LLM дважды.
   Вне объёма T-006, но ничем не ограничено — кандидат в T-008/T-009 или
   отдельную S-задачу.
6. **Флаки-риск в тесте event loop.** `test_link_handler.py:292-293` ждёт
   старта сервиса жёсткими 1,0 с и поллингом 100×0,01 с. На загруженном CI
   это источник нестабильности; надёжнее `await asyncio.to_thread(started.wait)`
   или `asyncio.Event` с `wait_for`. Разработчик прогнал файл 5 раз подряд —
   зелено, но запас по времени не гарантирован.

## P4 — типы и публичный API

7. **Расхождения в тест-дублях.** `_UnusedService.process(...) -> None`
   против `Protocol` с `SummaryResult`, `broken_service(settings: object) ->
   None` (`test_bootstrap.py:26-31, 64`). mypy в проекте нет, поведение не
   ломается, но контракт неточен.
8. **`handlers/__init__.py` реэкспортирует все шесть пользовательских
   текстов** ради удобства тестов — расширяет публичный API слоя; достаточно
   `link.py` или явного `__all__` с комментарием.

## Что ревью подтвердило хорошего

- Порядок «принял → обрабатываю → документ → готово» соблюдён: «принял»
  уходит до запуска фоновой задачи, документ — после проверки файла.
- `asyncio.to_thread` действительно уводит `SummaryService.process` из потока
  event loop (проверено по `threading.get_ident()`), loop остаётся живым,
  пока сервис заблокирован.
- Текст без ссылки не запускает обработку; из нескольких ссылок берётся
  первая; не-YouTube ссылка доходит до адаптера (доменная проверка — его
  ответственность, FR-2).
- `.md` существует на диске в момент `SendDocument`, имя — из шаблона
  заметки; `app/data/` в `.gitignore`.
- Тесты на фейковом боте (`FakeSession(BaseSession)` + `Dispatcher.feed_update`)
  без сети и реального токена.
- `handlers/` остаётся тонким: нет сетевых вызовов и бизнес-логики, только
  `SummaryProcessor.process` (ADR-002).
- Секретов, `print`, `TODO` в новом коде нет; защищённые пути не затронуты.

## Долг прошлых циклов: что не закрыто

- **P1 T-004 всё ещё открыт:** `httpx.InvalidURL` по-прежнему вылетает мимо
  `LLMError` (в `adapters/llm.py` ловится только `httpx.HTTPError`),
  отсутствующий ресурс/маркер по-прежнему даёт `RuntimeError`
  (`llm.py:357, 381`). T-006 это не чинил и не мог: он ловит любое исключение
  и показывает общее сообщение, то есть **маскирует** дыру до T-008.
- **P1 T-005 всё ещё открыт:** `SummaryService.process` не проверяет
  `TranscriptText.is_empty`; защита держится только на `YouTubeAdapter`.
  `handle_message` для текста без ссылки это не затрагивает, но пустой
  транскрипт дойдёт до LLM.
- **`_one_line` — по-прежнему три копии** (`services/note.py`,
  `adapters/youtube.py`, `adapters/llm.py`); `format_timecode` не
  дублируется. Новых копий T-006 не добавил: обработчик не форматирует
  таймкоды. Правило `shared-helpers` сработало.
- **Закрыт пункт релизных метаданных:** `tldw.__version__` синхронизирован с
  `pyproject.toml` (0.9.0), добавлен тест на совпадение, CHANGELOG дополнен.
  Это первый цикл, где долг по версиям закрыт.
- **P4 T-005** (округление таймкода, `str(item)`, `url.strip()`) не трогались.
