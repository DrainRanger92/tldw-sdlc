# Базовая линия TLDW после T-016: безопасные логи, явный fail-open и жизненный цикл

Дата: 2026-11-27. Срез после T-016 (цикл 16, коммит оркестратора —
0.20.0 → 0.21.0). Это текущее состояние `app/` для следующего цикла:
T-017 (единый источник помощников/лимитов) и T-018 (тесты/README/
упаковка) ещё в бэклоге 003, долг ≈62.

## Что умеет приложение

- **Telegram-сценарий:** ссылка → транскрипт → конспект LLM → `.md` для
  Obsidian; `/template` и кнопка «Шаблон» (1–12 разделов, тон 0–1000,
  разбор текста через LLM, кандидат только после «Сохранить»); голосовое
  описание ≤ 60 с идёт тем же путём, что текст; allowlist по user ID,
  понятные ошибки, README и E2E.
- **Логи централизованы:** `tldw/logging_setup.py::configure_logging`
  ставит `SanitizingFilter` на root и его обработчики, поэтому
  `cli.py`, старт/остановка и сторонние логгеры не пишут `Bearer`-токены,
  env-ключи и полный транскрипт. `errors.sanitize_log_text` /
  `sanitize_log_block` — те же правила для stderr; URL в причине
  сводится к `схема://host`, query и путь вырезаются.
- **Доступ:** `AccessPolicy.open()` и `MISSING_ALLOWLIST_WARNING` —
  забытый allowlist даёт `WARNING` и явную открытую политику, пустой
  кортеж остаётся документированным «доступ всем»; отказы логируются
  `DenialLogLimiter` (первый — `WARNING`, повторы — `DEBUG`, предел
  `MAX_TRACKED_DENIALS`); ответ «доступ закрыт» обёрнут и не роняет
  обработчик.
- **Ссылка и конкурентность:** `_LINK_RE` с левой границей
  `(?<![\w.-])` не ловит `notyoutube.com`/`not_youtube.com`; лог ошибки
  содержит только `video_id` или host; `LinkHandler` дедуплицирует по
  `(chat_id, user_id, video_id or url)`, резервирует слот до первого
  `await`, `MAX_CONCURRENT_LINKS = 2` (захардкожен, очередь не
  ограничена — T-017), `aclose()` отменяет фоновые задачи, `cli.main`
  закрывает приложение на любом пути, ошибка закрытия не вылетает из
  `main()`.
- **Ошибки:** `format_traceback` сохраняет деревом `ExceptionGroup`
  (с пределом глубины) и все строки длинных кадров; известные ошибки
  остаются видимы при `LOG_LEVEL=ERROR` — `_visible_level` поднимает
  уровень до порога (осознанный компромисс: запись отличима текстом);
  `max_tokens`/`*_TOKENS` не считаются секретами, а `SECRET_KEY`/
  `PASSWORD_HASH`/`AWS_SECRET_ACCESS_KEY` скрываются.
- **LLM-промпт:** `title`/`channel` экранируются как данные,
  `</transcript>` в теле не ломает структуру; в логах HTTP-ошибок
  только код ответа, без `reason_phrase`; `ensure_data_dir` вызывается
  до `Bot`; файловый I/O в корутинах — через `asyncio.to_thread`;
  `unique_user_ids`/`AccessPolicy.is_open` — один источник правил.

## Чего ещё нет (не предлагать как готовое)

- Ограничения очереди ссылок и выноса `MAX_CONCURRENT_LINKS` в env —
  нет (задокументировано, T-017).
- Второго сценария/FSM-состояний для голоса нет; `SPEECH_*`
  необязательны, без них — текстовый fallback; аудио и распознанный
  текст не пишутся в лог и `DATA_DIR`.
- `_media_type` всё ещё даёт plain `ValueError` (P2 T-013 → T-018).
- Веб-интерфейса, БД, деплоя и монетизации нет — вне vision.
