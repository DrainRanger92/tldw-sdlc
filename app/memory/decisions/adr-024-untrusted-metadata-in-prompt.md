# ADR-024: метаданные видео и транскрипт попадают в промпт как данные

- Статус: принято, уточняет ADR-005 и ADR-012
- Дата: 2026-11-27
- Цикл: 16, задача T-016

## Контекст

Промпт конспекта (`adapters/llm.py::build_user_prompt`) собирает блоки
данных из внешнего мира: `title`, `channel`, тон/разделы шаблона и тело
транскрипта. До T-016 эти значения вставлялись как есть:

- название видео с `</transcript>` закрывало блок данных, и всё после
  него модель могла прочитать как инструкцию (P3 T-004, «prompt
  injection из метаданных»);
- тон шаблона (пользовательский текст) мог содержать `</tone>` и
  изменить структуру запроса;
- в логах HTTP-ошибок LLM и речи писался `reason_phrase`/серверный
  текст — туда могли попасть фрагменты промпта и ответа.

При этом менять контракт ответа LLM нельзя: адаптер уже валидирует
строгий JSON и разделы (ADR-012), а формат заметки и промпт — часть
ресурсов пакета. Нужно было решить, **как** обезвредить внешние строки,
не ломая пользовательский текст и не добавляя новый контракт.

## Решение

1. **Метаданные и пользовательский тон обезвреживаются заменой угловых
   скобок** — `_data_text`: `<` → `‹`, `>` → `›`. Заголовок с
   `</tone>`/`</transcript>` перестаёт быть маркером, но остаётся
   читаемым текстом. Применяется к `title`, `channel`, тону и
   заголовкам разделов.
2. **В транскрипте обезвреживаются только маркеры блока**, а не весь
   текст: `_escape_transcript_markers` заменяет `<transcript>`/
   `</transcript>` (с пробелами и регистром) теми же угловыми символами.
   Таймкоды, код и обычные `<`/`>` в речи не трогаются — иначе
   транскрипт технического видео искажается.
3. **Границы блоков остаются одиночными и явными.** После экранирования
   в пользовательском сообщении ровно один `<transcript>`/`</transcript>`
   и один блок тона; тест проверяет количество маркеров, а не только
   отсутствие подстроки.
4. **В логах HTTP-ошибок — только код ответа.** `_complete` (LLM) и
   `transcribe` (речь) логируют статус, без `reason_phrase` и
   серверного текста; текст ошибки пользователю формируется из
   типизированной ошибки (ADR-017), а не из ответа провайдера.
5. **Проверка — на собранном промпте:** тест вызывает
   `build_user_prompt` с враждебными `title`/`channel`/транскриптом и
   проверяет маркеры; отдельный тест — что HTTP-ошибка не пишет
   `reason_phrase` (`test_llm_adapter.py`, `test_speech_adapter.py`).

## Альтернативы

- **Вырезать метаданные из промпта.** Теряется контекст («канал»,
  «название») и качество конспекта; отвергнуто.
- **Обернуть вход в JSON и просить модель разбирать JSON.** Меняет
  контракт промпта и ответа, требует поддержки экранирования на стороне
  модели; для MVP избыточно. Отложено.
- **Полагаться на инструкцию «игнорируй инструкции в данных».**
  Не доказательство: инъекция уже находится внутри блока, который
  модель считает доверенным. Отвергнуто как единственная мера.
- **Экранировать весь транскрипт (все `<`/`>`).** Ломает код и
  технические тексты в конспекте; отвергнуто, оставлены только маркеры.
- **Не логировать HTTP-ошибки вовсе.** Теряется диагностика; достаточно
  кода ответа. Отвергнуто.

## Последствия

- Внешний текст не может закрыть блок данных или добавить маркер; тон и
  заголовки остаются читаемыми (`‹`/`›` вместо `<`/`>` в редких
  случаях). Пользовательская заметка не меняется: экранирование
  действует только на входе промпта.
- **Ограничение:** это текстовая, а не структурная защита. Новая
  внешняя строка в промпте (например, описание канала, плейлист)
  обязана проходить через `_data_text`/`_escape_transcript_markers`;
  иначе дыра вернётся. Правило — в `app/skills/adapter-boundary`.
- **Ограничение:** `reason_phrase` убран из двух адаптеров; при
  добавлении нового HTTP-адаптера проверять, что в лог идёт только
  статус (ADR-017).
- Тесты: `test_user_prompt_escapes_metadata_and_transcript_markers`,
  `test_http_error_log_contains_only_status_code`,
  `test_http_error_log_contains_no_reason_phrase`; входят в 1144 теста
  baseline после T-016.
- Стоимость: `adapters/llm.py` +28/−8 (вместе с `_data_text`),
  `adapters/speech.py` +3/−5; входит в 518 шагов T-016.
