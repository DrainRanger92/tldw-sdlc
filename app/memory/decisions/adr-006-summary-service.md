# ADR-006: контракт сервиса конспекта — композиция адаптеров, порог до LLM, усечение по сегментам, атомарная запись

- Статус: принято
- Дата: 2026-11-26
- Цикл: 5, задача T-005

## Контекст

T-005 соединяет готовые части в пользовательский сценарий «ссылка → `.md`»:
YouTube-адаптер (ADR-004) отдаёт `Video` с `Transcript`, LLM-адаптер (ADR-005)
отдаёт валидированный `VideoSummary`, модель заметки (ADR-003) умеет
`render_note`. Нужно решить, где живёт сценарий и как он ведёт себя в
крайних случаях. Требования:

- видео длиннее порога из конфига отвергается **без частичной заметки**;
- порог задаётся `Settings` (дефолт ~2 часа), поведение на границе
  `duration == порог` зафиксировано тестом;
- таймкоды транскрипта сохраняются в промпте; если транскрипт усекается, это
  документировано и не ломает JSON-ответ LLM;
- тесты идут офлайн, на фейковых адаптерах, без сети и токенов;
- T-006 вызовет сценарий из async-обработчика, T-008 — построит на его ошибках
  пользовательские сообщения;
- готовый `.md` сохраняется в `DATA_DIR` и не попадает в git.

## Решение

- **Сервис — композиция поверх протоколов, а не наследник адаптеров.**
  `SummaryService(video_source: VideoSource, summarizer: SummaryProvider, *,
  max_duration_seconds, max_transcript_chars, data_dir=None)` в
  `services/summary.py`. Протоколы — `VideoSource.fetch(url) -> Video` и
  `SummaryProvider.summarize(...) -> VideoSummary`; реальные адаптеры
  подставляются в `from_settings(settings, video_source, summarizer)`.
  Сервис не импортирует `httpx`, `yt_dlp`, `youtube_transcript_api` — граница
  слоёв ADR-002 сохраняется.
- **Единственная точка входа — `process(url)`.** Порядок жёсткий:
  `fetch` → проверка длительности → склейка/усечение транскрипта → `summarize`
  → `build_note` → `render_note` → запись файла. Синхронный: вызывающий слой
  уводит его в `asyncio.to_thread` (как и оба адаптера).
- **Порог проверяется сразу после `fetch`, до LLM и до записи.** `duration >
  max_duration_seconds` → `VideoTooLongError(duration_seconds,
  max_duration_seconds)`, ни LLM, ни файл не вызываются. `duration == порог`
  допускается; `duration is None` не блокирует (метаданные необязательны,
  ADR-004). Порог — `Settings.max_video_duration_seconds`,
  `DEFAULT_MAX_VIDEO_DURATION_SECONDS = 7200`.
- **Транскрипт для промпта — значение, а не строка.** `join_transcript`
  возвращает `TranscriptText(text, truncated, used_segments, total_segments)`;
  строки — `[MM:SS]`/`[HH:MM:SS]` через `format_timecode` из
  `services.note` (без новой копии помощника). Усечение — по границам
  сегментов (не по символам внутри строки), лимит
  `DEFAULT_MAX_TRANSCRIPT_CHARS = 80_000` символов, маркер
  `[транскрипт усечён: N из M сегментов]` входит в лимит; инструкция про
  маркер добавлена в `summary_prompt.md`, JSON-схема ответа не меняется.
- **Сборка заметки отделена от сценария.** `build_note(video, summary, *,
  source=None)` — чистая функция: `Note` из метаданных и `VideoSummary`.
  `source` по умолчанию — исходная ссылка пользователя, а не нормализованная
  адаптером; это зафиксировано тестом.
- **Результат — неизменяемое значение.** `SummaryResult(note, markdown,
  filename, transcript, path)` (`frozen=True, slots=True`); `path is None`,
  если `data_dir` не задан (предпросмотр и тесты без файлов).
- **Запись — отдельный слой `storage/`.** `note_path(data_dir, filename)`
  валидирует имя (только `.md`, без каталогов и `..`),
  `save_note(...)` пишет атомарно: `mkstemp` в целевом каталоге + `os.replace`,
  временный файл удаляется в `except BaseException`. Каталог берётся из
  `Settings.data_dir`, создаётся при записи.

## Альтернативы

- **Писать файл прямо в сервисе через `open()`.** При сбое посередине
  остаётся частичный `.md`, а пользователь получает «готово» на битый файл.
  `storage/` с `mkstemp` + `os.replace` даёт атомарность и переиспользование.
- **Резать транскрипт по символам.** Ломает строки `[MM:SS]` и учёт
  сегментов, из-за чего маркер усечения врёт. Режем по границам сегментов.
- **Отвергать видео с `duration is None`.** Метаданные необязательны
  (ADR-004): часть видео пришла бы с ложной ошибкой «слишком длинное».
- **Стримить/чанковать конспект для длинных видео.** Меняет контракт LLM и
  стоимость; вне MVP. Пока — лимит символов и явный маркер усечения.
- **Возвращать только строку Markdown.** T-006 нужны имя файла, путь и модель
  заметки (для логов и повторной отправки); `SummaryResult` отдаёт всё.
- **Держать сценарий в `handlers/`.** Смешало бы Telegram и бизнес-логику и
  сделало бы E2E-тест зависимым от aiogram.

## Последствия

- T-006 вызывает `process()` через `asyncio.to_thread` и ловит
  `VideoTooLongError` + типизированные ошибки адаптеров; `SummaryService` уже
  отдаёт готовый `.md`, обработчику остаётся отправка и сообщения.
- T-008 получает точку для текста «слишком длинное видео» из
  `VideoTooLongError` (порог и длительность в атрибутах).
- **Известная дыра (P1 в `t005-review-issues.md`).** `process` не проверяет
  пустой транскрипт: `TranscriptText.is_empty` есть, но не используется —
  через `YouTubeAdapter` недостижимо, однако защита должна быть в сервисе.
  Закрыть в T-006/T-008.
- Усечение считается в символах, а не в токенах: стоимость промпта
  ограничена ~80 тыс. символов, но не гарантирует лимит токенов модели.
- Тесты — 45 новых кейсов на фейковых адаптерах, полный набор 257, `ruff`
  зелёный; цикл стоил 94 шага и 79 тыс. output — в границах M, потому что
  задача оказалась композицией, а не новой интеграцией
  (`composition-is-cheaper-than-integration.md`).
- Релизные метаданные (`CHANGELOG`, версия) T-005 не трогала — остаётся
  расхождение 0.6.0/0.1.0 из `t004-review-issues.md`.
