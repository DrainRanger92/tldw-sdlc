# ADR-011: домен шаблона заметки и хранение JSON v1 на пользователя

- Статус: принято
- Дата: 2026-11-27
- Цикл: 10, задачи T-001, T-002

## Контекст

В MVP шаблон заметки был один и зашит в пакет: 7 полей frontmatter и 5 секций
(`adapters/resources/note_template.md`, `summary_prompt.md`). Спека 002
требует, чтобы пользователь задавал **свои разделы и тон**, а поведение по
умолчанию (FR-1) осталось прежним. Требования, определяющие решение:

- шаблон — упорядоченный список 1–12 заголовков (1–80 символов, уникальных
  без учёта регистра, без `#`, `---` и YAML frontmatter) плюс тон 0–1000
  символов; лимиты — константы кода (FR-2, FR-12);
- шаблон хранится отдельно на Telegram user ID в `DATA_DIR`, переживает
  перезапуск, запись атомарная, формат версионирован; отсутствующий,
  битый или неизвестный файл не роняет бота, а даёт встроенный шаблон
  (FR-3);
- сброс идемпотентен; чужой шаблон нельзя прочитать или изменить (FR-9,
  FR-10);
- слои не меняются: `handlers → services → adapters/storage` (ADR-002),
  `storage` не должен импортировать `services`;
- тесты офлайновые, без сети и токенов.

## Решение

- **Домен — новый нейтральный модуль `tldw/services/template.py`.**
  `NoteTemplate` — frozen dataclass (`sections: tuple[str, ...]`, `tone: str`)
  с нормализацией и валидацией в `__post_init__`; `ActiveTemplate` добавляет
  происхождение `builtin`/`user`; `BUILTIN_SECTIONS`/`BUILTIN_TEMPLATE` —
  ровно пять секций MVP в прежнем порядке. `services/note.py` строит из них
  прежние имена `SECTION_*`/`SECTION_HEADINGS`, поэтому публичный API заметки
  не ломается.
- **Слияние правки — доменная операция.** `TemplatePatch` (разделы и/или тон,
  `None` = «не менять», пустая строка тона = «очистить») и
  `TemplateService.merge_patch` сохраняют неизменённую часть; отсутствие
  изменений — `TemplateParseError`. `TemplateValidationError` и
  `TemplateParseError` — `UserFacingError` с русским текстом.
- **Хранилище — `tldw/storage/templates.py`, JSON v1.**
  `<DATA_DIR>/templates/<user_id>.json`:
  `{"version": 1, "sections": [...], "tone": "..."}`. `TemplateStore`
  реализует `TemplateRepository` **структурно** (duck typing) и обменивается
  примитивами `(разделы, тон)`, поэтому не импортирует домен. User ID —
  только положительный `int`; `bool`, строки, `0`, отрицательные и `../evil`
  отвергаются, имя файла собирается из числа.
- **Атомарная запись — общий `tldw/storage/atomic.py`.** `atomic_write_text`
  (временный файл рядом + `os.replace`, `fsync`, удаление `.tmp` при ошибке)
  используется и заметками, и шаблонами. Ошибка записи/удаления →
  `TemplateStorageError(UserFacingError)`, прежний файл не теряется.
- **Устойчивое чтение.** Отсутствующий файл, битый JSON, не-UTF-8, неверная
  схема и неизвестная `version` → `WARNING` и `None` (встроенный шаблон);
  файл не удаляется молча, чтобы его можно было починить или мигрировать.
- **Версия схемы — в файле, а не в env.** Будущая миграция меняет
  `SCHEMA_VERSION` и добавляет ветку чтения; лимиты и формат — код, не
  конфиг (FR-12).

## Альтернативы

- **Один общий JSON/БД на всех.** Проще, но нарушает изоляцию по user ID и
  вводит базу данных, которой нет в vision. Отвергнуто.
- **Хранить шаблон в FSM/памяти.** Кандидат не должен переживать перезапуск,
  но подтверждённый шаблон обязан (FR-3). Отвергнуто.
- **Хранить шаблон в env/`app/.env`.** Пользовательские данные в env —
  смешение секретов и настроек, невозможность записи из бота. Отвергнуто.
- **Валидировать лимиты в хранилище.** Продублировало бы домен и нарушило
  границу `storage ↛ services`; хранилище проверяет только схему файла.
- **Писать файл через `open()`.** Частичный `.md`/JSON при сбое и потеря
  прежнего шаблона; общий `atomic_write_text` уже был нужен заметкам.
- **Отдельный `TemplateRecord` в `storage` с dataclass.** Импорт домена из
  хранилища или третья копия модели; примитивы дешевле и достаточны.

## Последствия

- T-006/T-007/T-008 строят сценарий поверх `TemplateService`: разбор патча
  живёт в адаптере, слияние и лимиты — в домене, хранение — за протоколом.
- **Известный P2:** отсутствие файла шаблона (штатное состояние) пишется
  `WARNING` на каждую ссылку; следует различать «нет файла» (`DEBUG/INFO`) и
  «битый/неизвестный» (`WARNING`). См. `t001-t010-review-issues.md`.
- **Известный P3:** `MIN_SECTION_ITEMS`/`MAX_SECTION_ITEMS` объявлены в
  домене, но реальная проверка количества пунктов — в `adapters/llm.py`,
  то есть второй источник истины. Либо использовать константы в валидаторе
  адаптера, либо убрать их из домена.
- Запись стала общей для заметок и шаблонов; `storage/notes.py` переведён на
  `atomic_write_text` (поведение и тесты сохранены).
- Тесты: `test_template.py` (599 строк) и `test_storage_templates.py`
  (475 строк) покрывают лимиты, слияние, roundtrip, перезапуск, битый файл,
  неизвестную версию, изоляцию, атомарность и повторный `delete`; полный
  набор после T-002 — часть итоговых 828.
- Стоимость: T-001 — 57 шагов, T-002 — 32 шага (самая дешёвая задача цикла);
  чистый домен без проводки — это M1 (`estimate-m-bucket-wide.md`).
