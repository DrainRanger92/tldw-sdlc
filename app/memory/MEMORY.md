## Решения (ADR)

- [ADR-001: конфигурация только из env](decisions/adr-001-config-env-only.md) — fail-fast, секреты вне repr, `.env` не перетирает env.
- [ADR-002: слои пакета и адаптеры](decisions/adr-002-layered-adapters.md) — handlers → services → adapters/storage, сборка без сети.
- [ADR-003: модель заметки и ручной YAML-рендер](decisions/adr-003-note-model-manual-yaml.md) — frozen dataclasses и чистые функции в `services/note.py`, YAML вручную, PyYAML только в тестах.
- [ADR-004: контракт YouTube-адаптера](decisions/adr-004-youtube-adapter-contract.md) — два источника за протоколами, fallback yt-dlp, типизированные ошибки и их приоритет; внутренний контракт уточнён ADR-019 (один `extract_info`, таймаут сессии).
- [ADR-005: контракт LLM-адаптера](decisions/adr-005-llm-adapter-contract.md) — промпт/шаблон как ресурсы пакета, строгая JSON-валидация, повтор только на 429/5xx, `LLMError`.
- [ADR-006: контракт сервиса конспекта](decisions/adr-006-summary-service.md) — композиция за протоколами `VideoSource`/`SummaryProvider`, порог до LLM, атомарная запись.
- [ADR-007: Telegram-слой](decisions/adr-007-telegram-handler.md) — тонкий обработчик, «принял» до тяжёлых вызовов, фоновая задача + `to_thread`.
- [ADR-008: allowlist и правило доступа](decisions/adr-008-allowlist-access-policy.md) — `AccessPolicy` в `access.py`, проверка первой строкой `handle_message`, без aiogram-middleware.
- [ADR-009: пользовательские ошибки и очистка лога](decisions/adr-009-user-facing-errors.md) — нейтральный `errors.py`, `UserFacingError`, `describe_error`/`log_failure`, шаблоны секретов.
- [ADR-010: сквозной тест и общий тестовый каркас](decisions/adr-010-e2e-test-surface.md) — настоящие `Dispatcher`/`Handler`/`Service`/`storage`, фейки только на трёх внешних границах, общий `tests/support.py`, README под тестами.
- [ADR-011: домен шаблона и хранение JSON v1](decisions/adr-011-template-domain-storage.md) — `NoteTemplate`/`ActiveTemplate`/`TemplateService`, `TemplateRepository` примитивами, `<DATA_DIR>/templates/<user_id>.json`, общий `atomic_write_text`.
- [ADR-012: динамическая заметка и шаблонный промпт](decisions/adr-012-dynamic-note-llm-template.md) — `SectionKind`/`NoteSection` при сохранённом встроенном пути, строгая валидация ответа, тон как данные, `parse_template` и снимок шаблона.
- [ADR-013: Telegram-сценарий шаблона и проводка](decisions/adr-013-telegram-template-flow.md) — FSM `MemoryStorage`, кандидат только в памяти, allowlist первой строкой, порядок template → link, снимок `ActiveTemplate` в `SummaryService`.
- [ADR-014: гранулярность инкремента](decisions/adr-014-increment-granularity.md) — инкремент = единица ревью/коммита/версии; 2–3 задачи на инкремент, иначе одно ревью и отложенный долг; одна задача допустима для риска/безопасности.
- [ADR-015: распознавание речи — необязательная граница и текстовый fallback](decisions/adr-015-speech-adapter.md) — `SpeechAdapter`, необязательные `SPEECH_*`, один запрос, лимит 60 с, typed `SpeechError`, аудио/текст не в логе; T-012 встраивает голос в сценарий шаблона.
- [ADR-016: голосовое описание переиспользует текстовый сценарий](decisions/adr-016-voice-input-flow.md) — `handle_voice` в том же `TemplateHandler`, те же FSM-состояния и `_present_description`; allowlist → состояние → `is_configured` → лимит → `BytesIO` → `to_thread`; без `SPEECH_*` — текстовый fallback, аудио в памяти.
- [ADR-017: единый контракт ошибок HTTP-адаптеров и валидация URL](decisions/adr-017-typed-error-contract-url-validation.md) — `config.validate_http_url` (fail-fast, host/port/IPv6/Cc), обёртки `_make_client`/`post`, `InvalidURL`/`ValueError` → typed provider, `LLMConfigError`, `EmptyTranscriptError` до LLM, allowlist `media_type`; YouTube-адаптер закрыт ADR-019.
- [ADR-018: долг ревью — отдельная спека 003 с аудитом каждого пункта](decisions/adr-018-review-debt-spec-audit.md) — 6 задач T-013…T-018 в трёх батчах, id с T-013 (глобально уникальные), аудит «код/тест → актуален/устарел/процессный → доказательство», реестр в памяти; 1–2 задачи на инкремент; T-013 закрыла 9 групп, T-014 — 6 P1 T-003, T-015 — 13 пунктов, долг ≈80.

- [ADR-021: динамическая заметка сохраняет нативный формат разделов](decisions/adr-021-dynamic-note-native-format.md) — `_split_timecode` только для ведущего `MM:SS`/`HH:MM:SS`, цитата без таймкода без `> —`, нормализация в рендере, сквозной тест LLM → `SummaryService` → `render_note`; известный P3 — правая граница regex.
- [ADR-022: очистка логов централизована фильтром, известные ошибки поднимаются до порога](decisions/adr-022-centralized-log-sanitization.md) — `SanitizingFilter` на root и обработчики (`msg`/`args`/`exc_text`/`stack_info`), `sanitize_log_text` по месту для stderr и пользовательских текстов, URL → `схема://host`, секреты по формам с исключением `max_tokens`/`*_TOKENS`, `_visible_level` как осознанный компромисс, `DenialLogLimiter` с пределом; цена — известные ошибки при `LOG_LEVEL=ERROR` неотличимы по уровню от инцидентов, правка шаблонов требует двусторонних ловушек.
- [ADR-023: аудит дробится по 8 модулей, бюджет ревью считается раундами](decisions/adr-023-audit-splitting-review-budget.md) — M4+ только 5–8 модулей; > 8 модулей или > 15 пунктов — L (аудит), 2–3 тематических батча до EXECUTE, иначе 400–550 шагов и два раунда; FIX 0,5–0,7 × EXECUTE за раунд, REVIEW-2 1,5–1,9 ×; последний FIX при исчерпании лимита — явный процессный долг следующего цикла.
- [ADR-024: метаданные видео и транскрипт попадают в промпт как данные](decisions/adr-024-untrusted-metadata-in-prompt.md) — `_data_text` (`<`→`‹`, `>`→`›`) для `title`/`channel`/тона, `_escape_transcript_markers` только для маркеров блока, одиночные границы и тест на число маркеров; в логах HTTP-ошибок только код ответа; новая внешняя строка обязана пройти тот же помощник.
- [ADR-025: непроверенный FIX закрывается отдельной задачей-проверкой](decisions/adr-025-unverified-fix-separate-verification.md) — если `max_review_iterations` исчерпан, следующий инкремент — проверка последнего FIX до правки тех же модулей: состав по журналу сессии, таблица «правка → проверка → результат» в диффе, мутации, обе стороны; T-019 — 101 EXECUTE + 60 REVIEW + 61 ANALYZE = 222 шага, найден регресс `tokenizer`; задача-проверка — M3 по EXECUTE, но цикл 190–250.
