# TLDW — Telegram-бот: ссылка на YouTube → заметка для Obsidian

Приложение принимает ссылку на видео YouTube, получает транскрипт, просит LLM
сделать конспект и присылает готовый `.md`-файл: 7 полей frontmatter
(`title`, `source`, `channel`, `duration`, `date`, `tags`, `status`) и 5 секций
(`TL;DR`, «Ключевые идеи», «Таймкоды», «Цитаты», «Что проверить»). Файл
складывается в `DATA_DIR` и отправляется пользователю документом.

## Требования

- Python 3.11+;
- доступ к YouTube (транскрипты и метаданные видео);
- ключ и модель OpenAI-совместимого провайдера LLM;
- токен Telegram-бота от [@BotFather](https://t.me/BotFather).

## Установка

Из корня репозитория:

```bash
cd app
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

`[dev]` добавляет `pytest`, `pyyaml` и `ruff` — они нужны для тестов и линтера,
для запуска бота достаточно `.venv/bin/pip install -e .`.

## Переменные окружения

Все настройки читаются из переменных окружения. Файл `app/.env` лишь
подставляет значения для переменных, которых нет в окружении (реальный env
приоритетнее). Образец без секретов — [`.env.example`](.env.example):

```bash
cp .env.example .env
# заполните TELEGRAM_BOT_TOKEN, LLM_API_KEY и LLM_MODEL
```

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | токен бота от @BotFather, формат `<bot_id>:<секрет>` |
| `TELEGRAM_ALLOWED_USER_IDS` | нет | пусто | Telegram user ID через запятую или пробел; пусто — доступ всем (в лог пишется предупреждение) |
| `LLM_API_KEY` | да | — | ключ API провайдера LLM |
| `LLM_MODEL` | да | — | имя модели, например `deepseek-chat` |
| `LLM_BASE_URL` | нет | `https://api.deepseek.com` | базовый URL OpenAI-совместимого API |
| `LLM_TIMEOUT_SECONDS` | нет | `60` | таймаут одного запроса к LLM, секунды |
| `VIDEO_MAX_DURATION_SECONDS` | нет | `7200` | порог длительности видео, секунды (2 часа) |
| `DATA_DIR` | нет | `data` | каталог заметок и кэша; относительный путь считается от `app/` |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |

Секреты (`TELEGRAM_BOT_TOKEN`, `LLM_API_KEY`) нельзя хранить в коде, тестах,
README или коммитить: `.env` уже в `.gitignore`. При неполной конфигурации
приложение завершается с понятным сообщением и кодом 2.

## Проверка конфигурации без запуска бота

```bash
.venv/bin/python main.py --check-config
```

Команда читает env/`.env`, собирает приложение и выходит, не подключаясь к
Telegram. Успех — код 0, ошибка конфигурации — сообщение и код 2.

## Запуск

Из каталога `app`:

```bash
.venv/bin/python main.py
```

Или из корня репозитория:

```bash
aidevteam app dev
```

Остановка — `Ctrl+C`. При старте в лог пишется модель LLM и режим доступа; если
`TELEGRAM_ALLOWED_USER_IDS` пуст, появляется предупреждение, что бот открыт всем.

## Ручная проверка на реальной ссылке YouTube

1. Запустите бота (см. выше) и убедитесь, что ваш Telegram user ID разрешён:
   либо он есть в `TELEGRAM_ALLOWED_USER_IDS`, либо список пуст.
2. Откройте чат с ботом и отправьте ссылку на публичное видео с субтитрами,
   например:

   ```text
   https://www.youtube.com/watch?v=dQw4w9WgXcQ
   ```

   Замените её на любое доступное видео с субтитрами длительностью до
   `VIDEO_MAX_DURATION_SECONDS`.
3. Ожидаемая последовательность сообщений:

   ```text
   ✅ Принял ссылку.
   ⏳ Обрабатываю видео…
   <имя-заметки>.md      (документ)
   ✅ Готово.
   ```

   Обработка занимает от нескольких секунд до минуты: сначала бот отвечает
   «принял», чтобы запрос не потерялся, а тяжёлая работа идёт в фоне.
4. Проверьте результат:
   - в `DATA_DIR` (по умолчанию `app/data/`) появился `.md` с именем-slug
     заголовка видео;
   - файл открывается в Obsidian и содержит YAML frontmatter с 7 полями и все
     5 секций шаблона;
   - значение `source` в frontmatter равно отправленной вами ссылке.
5. Проверьте негативные сценарии — каждый даёт своё сообщение, без стектрейса:
   - текст без ссылки → подсказка прислать ссылку YouTube;
   - видео без субтитров → «У этого видео нет субтитров…»;
   - видео длиннее порога → «Видео слишком длинное: …»;
   - чужой Telegram ID при заданном allowlist → «⛔ Доступ закрыт…»;
   - сбой LLM → «AI не ответил. Попробуйте позже.».

При ошибке заметка не создаётся: ни `.md`, ни временных файлов в `DATA_DIR` не
остаётся.

## Тесты и линтер

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

Тесты полностью офлайновые: Telegram, YouTube и LLM подменены фейками, сеть и
реальные токены не нужны. Сквозной сценарий «ссылка → `.md`» и ошибочные кейсы
проверяются в `tests/test_e2e.py`.

## Структура приложения

```text
app/
├── main.py                  точка входа
├── tldw/
│   ├── cli.py               проверка конфигурации и запуск
│   ├── config.py            настройки из env/.env
│   ├── bootstrap.py         сборка бота, диспетчера и сервиса
│   ├── handlers/            Telegram-слой (ссылка, allowlist, ответы)
│   ├── services/            конспект, модель заметки, рендер Markdown
│   ├── adapters/            YouTube, LLM и ресурсы промпта/шаблона
│   ├── storage/             атомарная запись заметок в DATA_DIR
│   └── errors.py            понятные ошибки и очистка лога от секретов
└── tests/                   офлайновые тесты (pytest)
```

## Безопасность

- Токен бота и ключ LLM передаются только через env/`.env`; в коде, тестах и
  документации их нет.
- Логи очищаются от токенов, ключей API и длинных фрагментов транскрипта;
  полные ссылки и `video_id` намеренно не логируются.
- Каталог `data/`, `.env` и `.venv/` исключены из git.
